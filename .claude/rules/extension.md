# Extension

[docs/ARCHITECTURE.md](../../docs/ARCHITECTURE.md#extension) defines the layers and the security model. Key rules:

- **Thin entrypoints.** `src/entrypoints/*` only call a `start*` function from `src/background`, `src/content`, or `src/dashboard`, or, in the cross-profile POC (development and test builds only), `src/offscreen`. `src/tabs` is the one tab model (normal and incognito) and its event-driven source, read by the dashboard and its PiP window; it imports no other app folder but `src/ports`. The dashboard starter takes one `ExtensionServices` object (`src/views/extension-services.ts`): the entrypoint builds the real one, and tests pass `fakeExtension()` from `tests/fake-extension.ts`. Logic lives in those folders, where unit tests reach it without WXT globals. Nothing imports an entrypoint.
- **Ports.** `src/ports` holds the type-only contracts every folder may import with `import type`: `RecordingStore` (implemented by `src/storage`, used by the background and the views), `TabSource` (implemented by `src/tabs`), `IncognitoAccess` (implemented by `src/dashboard/incognito-access.ts`), and `ToolbarPin` (implemented by `src/dashboard/toolbar-pin.ts`). It imports only `@recnrun/domain`; dependency-cruiser rejects a runtime import of it and any other import from it. Pure session math (`elapsedSeconds`, `toggled`, `formatElapsed`) and `errorMessage` live in `@recnrun/domain`, not in the views.
- **Allowed origins.** `src/config/origins.ts` is the only list of pages the content script runs on. Production builds match only `https://recnrun.com/*` (the other project domains only redirect there); `development` and `test` builds add `localhost` and `127.0.0.1`. `vp run test:extension-manifest` fails if a production manifest matches more, or asks for permissions other than `storage` and `tabs`, or declares host permissions, optional permissions, optional host permissions, `externally_connectable`, a `content_security_policy`, commands, or a popup, or sets `incognito` to anything but `spanning`, or lets a content script run outside the top frame of a real document (`all_frames`, `match_about_blank`, `match_origin_as_fallback`). It also fails on any `web_accessible_resources`: no web page may load or frame an extension page, so the dashboard is only ever its own tab.
- **Messaging.** The content script is only a relay and adds nothing to the page: it accepts bridge requests from its own page (`@recnrun/bridge` host), forwards them with `browser.runtime.sendMessage`, and returns the background's reply. It never touches storage: dependency-cruiser rejects an import of `src/storage` or `wxt/utils/storage` from `src/content`, and lint rejects `browser.storage` there; a compromised page must not reach more than the background chooses to answer.
- **Validation.** The background has one `runtime.onMessage` listener (`src/background/listener.ts`). It validates every message once with `BackgroundMessageSchema` (`src/messaging/background-messages.ts`, a `variant` on `type` over the bridge request types and the session requests), classifies the sender as `offscreen` (its own `offscreen.html`), `ownPage` (its own extension id and another URL on its origin), or `contentScript` (its own id in a web page) and ignores any other, then dispatches through the route table in `src/background/routes.ts`, where each message type names the senders it accepts: bridge requests from `ownPage` or `contentScript`, session and `peer` requests from `ownPage` only, `link` events from `offscreen` only. Adding a message type means a new `variant` option and a new `case`; the exhaustive `switch` fails type checking until the case exists. Every accepted message gets a `BackgroundReplySchema` reply: `{ ok: true, result }` for a bridge request, `{ ok: true }` for a session request, and `{ ok: false, error }` when the route fails. Stored data is validated with the domain schemas when read; invalid stored data is an error reply, never a partial result and never a value to overwrite. The pages validate the reply and show the error.
- **Incognito.** Never store an incognito tab's title or URL, and never load its favicon URL from the extension (it would carry the normal context's cookies). To try it in the dev Chrome, turn on Developer mode before "Allow in Incognito": otherwise Chrome disables the unpacked extension when the toggle reloads it.
- **Storage.** Use WXT's `storage` (`wxt/utils/storage`) through a repository in `src/storage`; keys are `local:<name>`, or `session:<name>` for state that must end with the browser (the recording in progress). Change the stored shape only together with `SNAPSHOT_SCHEMA_VERSION` handling in `@recnrun/domain`.
- **Cross-profile POC.** `src/p2p`, `src/offscreen`, and `src/peers` exist only in `development` and `test` builds (`peersEnabled` in `src/config/origins.ts`); keep every use behind that mode check, so the production manifest guard keeps passing. Validate every DataChannel frame with `parsePeerFrame` and accept it only through `src/background/peer-channel.ts`; never put page content, storage, cookies, or incognito tabs in a peer message.
- **Permissions.** Ask for no permission or host permission the current feature does not use. Adding one updates `apps/extension/scripts/manifest.checks.mjs` and the security model in the docs.
- **Imports.** WXT auto-imports are off (`imports: false`); import from `wxt/browser`, `wxt/utils/*`, and `@/` explicitly.
- **Tests.** Unit tests use `WxtVitest` and `fakeBrowser` (`wxt/testing/fake-browser`); reset it in `beforeEach`. Dashboard components run in Vitest Browser Mode. End-to-end tests load `.output/chrome-mv3-test`, built by `vp run extension#build:test`.

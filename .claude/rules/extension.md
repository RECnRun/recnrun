# Extension

[docs/ARCHITECTURE.md](../../docs/ARCHITECTURE.md#extension) defines the layers and the security model. Key rules:

- **Thin entrypoints.** `src/entrypoints/*` only call a `start*` function from `src/background`, `src/content`, `src/dashboard`, `src/session`, or `src/origin`. `src/tabs` is the one tab model (normal and incognito) and its event-driven source, read by the dashboard and the session; it imports no other app folder but `src/ports`. The page starters take one `ExtensionServices` object (`src/views/extension-services.ts`): the entrypoint builds the real one, and tests pass `fakeExtension()` from `tests/fake-extension.ts`. Logic lives in those folders, where unit tests reach it without WXT globals. Nothing imports an entrypoint.
- **Ports.** `src/ports` holds the type-only contracts every folder may import with `import type`: `RecordingStore` (implemented by `src/storage`, used by the background and the views), `TabSource` (implemented by `src/tabs`), `IncognitoAccess` (implemented by `src/dashboard/incognito-access.ts`), and `SitePort`. It imports only `@recnrun/domain`; dependency-cruiser rejects a runtime import of it and any other import from it. Pure session math (`elapsedSeconds`, `toggled`, `formatElapsed`) and `errorMessage` live in `@recnrun/domain`, not in the views.
- **Allowed origins.** `src/config/origins.ts` is the only list of pages the content script runs on. Production builds match only `https://recnrun.com/*` (the other project domains only redirect there); `development` and `test` builds add `localhost` and `127.0.0.1`. `vp run test:extension-manifest` fails if a production manifest matches more, or asks for permissions other than `storage` and `tabs`, or declares host permissions, optional permissions, optional host permissions, `externally_connectable`, a `content_security_policy`, commands, or a popup, or sets `incognito` to anything but `spanning`, or lets a content script run outside the top frame of a real document (`all_frames`, `match_about_blank`, `match_origin_as_fallback`). The same origins are the only ones that may frame `dashboard.html` and `session.html` (their `web_accessible_resources` matches) and the only ancestors those pages render under; with no ancestor they only point to the site.
- **Messaging.** The content script is a relay: it accepts bridge requests from its own page (`@recnrun/bridge` host), forwards them with `browser.runtime.sendMessage`, and returns the background's reply. It never touches storage: dependency-cruiser rejects an import of `src/storage` or `wxt/utils/storage` from `src/content`, and lint rejects `browser.storage` there; a compromised page must not reach more than the background chooses to answer. The origin agent (`src/origin`, POC) is the other content script and follows the same rule (`extension-origin-agent-isolated`, the same lint): it writes the site's own storage, reaches the extension only through its port (`messaging/origin-protocol.ts`), and acts only on a valid first `restore` or `capture`, which the background sends only to the expected document (`background/workspace/agent-link.ts`).
- **Validation.** The background has one `runtime.onMessage` listener (`src/background/listener.ts`). It validates every message once with `BackgroundMessageSchema` (`src/messaging/background-messages.ts`, a `variant` on `type` over the bridge request types, the session requests, and the workspace requests), classifies the sender as `ownPage` (its own extension id and a URL on its origin) or `contentScript` (its own id in a web page) and ignores any other, then dispatches through the route table in `src/background/routes.ts`, where each message type names the senders it accepts: bridge requests from either, session and workspace requests from `ownPage` only. Adding a message type means a new `variant` option and a new `case`; the exhaustive `switch` fails type checking until the case exists. Every accepted message gets a `BackgroundReplySchema` reply: `{ ok: true, result }` for a bridge request and `workspace-status`, `{ ok: true }` for the other session and workspace requests, and `{ ok: false, error }` when the route fails. Stored data is validated with the domain schemas when read; invalid stored data is an error reply, never a partial result and never a value to overwrite. The pages validate the reply and show the error. The `recnrun-frame` channel works the same way: `subscribeFrame(page, from, origin, handlers)` in `src/messaging/frame-channel.ts` checks the source window and origin, validates once with `FrameMessageSchema` (a `variant` on `type` over the six frame messages in `frame-protocol.ts`), and calls the handler for the type; the content script, each extension page, and the PiP window (`pip/document-pip.ts`) register one `message` listener through it, never their own. Both page starters render through `views/framed.tsx`, the one ancestor guard.
- **Incognito.** Never store an incognito tab's title or URL, and never load its favicon URL from the extension (it would carry the normal context's cookies). To try it in the dev Chrome, turn on Developer mode before "Allow in Incognito": otherwise Chrome disables the unpacked extension when the toggle reloads it.
- **Storage.** Use WXT's `storage` (`wxt/utils/storage`) through a repository in `src/storage`; keys are `local:<name>`, or `session:<name>` for state that must end with the browser (the recording in progress). Change the stored shape only together with `SNAPSHOT_SCHEMA_VERSION` handling in `@recnrun/domain`. The one exception is `src/storage/identity-captures.ts` (POC), which keeps identity captures in the extension's IndexedDB because WXT `storage` cannot hold `Blob` or `Date` values; it validates with `IdentityCaptureSchema` and versions with `IDENTITY_CAPTURE_VERSION`, and its writes stay atomic per transaction, with `publish` the only step that makes a capture visible.
- **Permissions.** Ask for no permission or host permission the current feature does not use. Adding one updates `apps/extension/scripts/manifest.checks.mjs` and the security model in the docs.
- **Imports.** WXT auto-imports are off (`imports: false`); import from `wxt/browser`, `wxt/utils/*`, and `@/` explicitly.
- **Tests.** Unit tests use `WxtVitest` and `fakeBrowser` (`wxt/testing/fake-browser`); reset it in `beforeEach`. Dashboard components run in Vitest Browser Mode. End-to-end tests load `.output/chrome-mv3-test`, built by `vp run extension#build:test`.

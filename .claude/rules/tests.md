# Tests

## Layers

| Layer       | Files                                                                    | Command                   |
| ----------- | ------------------------------------------------------------------------ | ------------------------- |
| Node unit   | `{apps,packages}/*/tests/*.test.ts`, `tests/*.test.ts` (the lab harness) | `vp run test:unit`        |
| Component   | `*.browser.test.ts(x)` in Vitest Browser Mode, Chromium                  | `vp run test:components`  |
| End-to-end  | `tests/e2e/*.spec.ts`, headed Playwright, built website + test extension | `vp run test:e2e`         |
| Browser     | `tests/browser/*.spec.ts`, Google Chrome Stable over CDP, headed on Xvfb | `vp run test:browser`     |
| Experiments | `tests/experiments/*.spec.ts`, POC hypotheses on the browser fixtures    | `vp run test:experiments` |
| Host        | `tests/host/*.spec.ts`, the Mac's installed Google Chrome, never Docker  | `vp run test:host`        |
| Scripts     | `scripts/*.checks.mjs` (Node)                                            | `vp run test:scripts`     |

- Keep schemas, protocol handling, handlers, and view models in Node unit tests; extract pure functions when that makes a rule testable.
- Both apps' `vitest.browser.config.ts` call `browserProject(name, dir)` from the root `vitest.browser.shared.ts`; change the Browser Mode setup there, once.
- Prove detection, the install banner, data display, origin checks, and CSP end to end, with the real extension loaded.

## Running

- Public commands run in Docker, headed Chromium (end-to-end) or Google Chrome Stable (browser) on an isolated Xvfb display. Keep `headless: false` (extensions need a headed Chromium), and never connect the container display to the host.
- `scripts/test-container.mjs` runs every target on `recnrun-tests`, an internal Docker network it creates once and never removes: the container keeps `lo` and `eth0`, and the image's entry (`scripts/test-container-entry.sh`, run with `--cap-add NET_ADMIN`) adds an on-link default route because a page's WebRTC binds its host candidate to the default-route address; DNS and every route out still fail, as `tests/browser/no-egress.spec.ts` proves (POC PLAN.md P1.0).
- Browser tests stay serial (`--workers=1`), coverage included.
- The Node projects run with `isolate: false`, so files of one project share a worker: reset module state in `beforeEach` (as `fakeBrowser.reset()` does) instead of relying on a fresh module per file.
- Pass Playwright arguments after `--`, for example `vp run test:e2e -- tests/e2e/dashboard-tab.spec.ts -g 'empty'`.
- On failure, read `.artifacts/docker/<run-id>/` (`run.log`, `test-results`, `playwright-report`, `evidence`, and `versions.json` with the image's Chrome, Node, pnpm, and Playwright versions).

- `vp run test:coverage` also fails when the measured file set differs from the source tree minus the configured excludes, or when any file with executable code is under the per-file floor of 80% lines, statements, and functions and 75% branches (`scripts/coverage.checks.mjs`); a new source folder outside `apps/*/src` or `packages/*/src` needs that script and `coverage.include` updated together. Lift a file under the floor with tests of its behavior, never by excluding it.
- `:local` variants open host windows; use them only for debugging.

## Writing end-to-end tests

- Import `test` and `expect` from `tests/e2e/fixtures/extension.ts` when the extension must be loaded; it launches a persistent Chromium context with `apps/extension/.output/chrome-mv3-test` and exposes `serviceWorker` and `seedSnapshot(snapshot)`. With `test.use({ remoteDebuggingPort })`, `clickToolbarIcon(page)` fires the real toolbar action on that page's tab (browser-level CDP `Extensions.triggerAction`), user gesture included. `test.use({ incognitoAccess: true })` starts from a profile that already allows the extension in Incognito. `tests/e2e/fixtures/session.ts` opens dashboard tabs (`openDashboard`), locates the PiP window and tab items, and opens the session; `fixtures/tabs.ts`'s `installedDashboard` finds the tab RECnRun opened at install. `tests/e2e/fixtures/tabs.ts` reads Chrome's tabs and the stored session through the service worker, since Playwright emulates focus; it also opens incognito tabs, moves the real focus (`focusTab`), and reads every stored value as text (`storedText`) for privacy checks. Import from `@playwright/test` for a browser without the extension.
- Seed data through `seedSnapshot` with fixtures from `@recnrun/domain/testing`; never drive the website into a state the extension could not produce.
- Locate by role and accessible name (`getByRole("article", { name })`, `getByRole("region", { name })`), not CSS classes.
- Prefer locator auto-waiting and `expect.poll` over fixed sleeps.
- Chrome's own folder picker and File System Access prompts are driven by `tests/e2e/fixtures/native-dialogs.ts`: import its `test`, and the `native` fixture gives an empty folder on the container's disk and `dialogs(page)`, to call before the click that opens the picker (it turns Playwright's chooser interception off on that page and brings it to the front); `answerRestorePrompt` answers in a normal window. Cross-profile tests pair through the dashboard with `pair(a, b, native)` from `fixtures/folder.ts`; `allowFolder` answers whichever prompt Chrome shows and returns which, so assert it only where Chrome is consistent: the restore prompt once a kept grant ended (an unlinked dashboard first closes the offscreen document, whose handles would hold the picker's grant), the write prompt after a revoke. Never mock `showDirectoryPicker`. It runs only in the container (`xdotool` on the Xvfb display, and `fixtures/display.ts` reads pixels with `scrot` to wait for each prompt), and the grant Chrome gives ends with the extension's last top-level page, so keep one open until the test has what it needs ([TROUBLESHOOTING.md](../../docs/TROUBLESHOOTING.md)).
- Security tests use a second origin through `context.route` (see `origin-guard.spec.ts`) and assert that forged messages get no answer.

## Writing browser tests (the POC lab)

- The lab runs Google Chrome Stable from the image, never Playwright's Chromium (which is Google Chrome for Testing): every run there is labelled `diagnostic` and approves nothing ([POC PLAN.md decision 2](../../docs/poc/downloads-launcher/PLAN.md#2-decisions)).
- Import `test` and `expect` from `tests/browser/fixtures/chrome.ts`. Its `chrome` fixture launches Google Chrome Stable headed with a throwaway `--user-data-dir`, waits for `DevToolsActivePort`, connects with `chromium.connectOverCDP` on the loopback, and exposes `browser`, `cdp` (a browser-target CDP session), `version`, `userDataDir`, `pid`, and `flags`; teardown keeps `display.png` of a failed test, stops Chrome with SIGTERM (its orderly quit on Linux), and deletes the root. `launchChrome({ userDataDir })` reuses a root across launches and leaves it in place; `launchChrome({ cdp: false })` starts the strict lab's Chrome with no `--remote-debugging-*` flag and no Playwright connection, and its `StrictChrome` has no `browser`, `cdp`, or `wsEndpoint` by type.
- Chrome 137 and later ignore `--load-extension` on branded builds, so the harness never passes it. `tests/browser/fixtures/extension-loaders.ts` installs `EXTENSION_PATH` (`apps/extension/.output/chrome-mv3-test`, built by `test:browser:local` and `test:experiments:local`), or `extensionPath(variant)` for a POC build (`poc-d0` is built by `test:experiments:local` and `test:host`), with `Extensions.loadUnpacked` over CDP, Chrome started with `--enable-unsafe-extension-debugging` (label `diagnostic`), and `attachExtension` pings its service worker through `cdp-client.ts`, retrying a ping that gets no answer in 3 s (right after a reinstall the old worker's target can still be listed). `openPage` in `cdp-client.ts` opens an extension page or `chrome://extensions` in a tab of its own (`Target.createTarget`, attach, evaluate, close), and a command on a session whose target detached rejects with `CdpDetachedError`. `tests/browser/fixtures/policy-install.ts` is the strict install (label `strict`): it packs the build as a CRX3 signed with a fresh key (`crx3.ts`; the test build has no `key`), serves it from an update server on `127.0.0.1`, writes `ExtensionInstallForcelist` to `/etc/opt/chrome/policies/managed/recnrun.json` (root on Linux inside the test container only, `RECNRUN_TEST_CONTAINER=1` and `/.dockerenv`, else `UnavailableError`; created exclusively, and removed only while it holds what that install wrote), and `launchStrict` starts Chrome with no CDP client; `installedState` reads the root's `Extensions/` folder and preferences after Chrome quits, and the dashboard window RECnRun opens on install and startup shows the extension ran.
- Experiments record each hypothesis with `appendVerdict` (`tests/experiments/verdicts.ts`) in `.artifacts/evidence/<RECNRUN_RUN_ID>/verdicts.json`, with `chrome`, `environment`, `install`, `label`, `variant`, `topology`, `debugger`, `externalClient`, `samples`, `gestures` and `steps` (the gestures a sample needed, such as a toggle clicked at `chrome://extensions`), and each sample's observations; `recordHypothesis` in `tests/experiments/outcome.ts` takes the samples and writes the verdict, and host twins pass it their `evidence().directory`. A hypothesis that fails is a verdict, not a test failure; the spec fails when a hypothesis left none. Docker runs set `RECNRUN_RUN_ID` to the run id and export the folder to `.artifacts/docker/<run-id>/evidence/`. `playwright.experiments.config.ts` never retries, since a retry would append a second verdict.
- **Sample counts** come from `sized(full, few = 1)` in `tests/experiments/samples.ts`, never from a literal. `vp run verify` sets `RECNRUN_EXPERIMENT_SAMPLES=smoke`, so every experiment runs once per hypothesis and `appendVerdict` stamps `mode: "smoke"`; `vp run test:experiments` runs the full counts and writes the evidence reports cite. A verdict with `mode: "smoke"` is never evidence.

- `tests/browser/fixtures/chrome-profiles.ts` gives `chromeA` and `chromeB`: Google Chrome Stable profiles on throwaway roots of their own, the test build installed by `loadUnpacked`, each with a page of the website and a named dashboard, shaped as tests/e2e's `Profile`, so `pair(a, b, native)` from `tests/e2e/fixtures/folder.ts` pairs them through Chrome's own picker and prompts (`tests/browser/mesh-two-profiles.spec.ts`). `playwright.browser.config.ts` serves the built website for them, as `playwright.config.ts` does.
- **Host runs.** `vp run test:host -- <spec>` builds the test extension and the `poc-d0` build and runs `playwright.host.config.ts` on the Mac itself (never Docker, never `verify`; `scripts/test-container.mjs` refuses it). No Docker runner strips the `--`, so Playwright reads everything after it as file filters: pass a grep without it (`vp run test:host tests/host/chrome.spec.ts -g 'stops only'`). Its global setup and `tests/host/fixtures/host-chrome.ts` refuse to start unless `RECNRUN_HOST_ROOTS` resolves, symlinks included, to `~/Documents/RECnRun/poc-downloads-launcher/` or a folder inside it (`tests/host/fixtures/roots.ts`). `hostExtension` launches `/Applications/Google Chrome.app` on a fresh `roots/<run>/<name>/` root there (created exclusively, so an existing folder or a symlink in its place is refused, and marked with a `.recnrun-host-root` file holding the run id), offscreen and with `--use-mock-keychain`, installs the build by `Extensions.loadUnpacked` (label `diagnostic`), writes `versions.json` (`Browser.getVersion`, `sw_vers`) under `.artifacts/evidence/host/<run>/`, stops only the PID it spawned, and deletes the root, never through a symlink and only when it holds its run's marker, unless `RECNRUN_HOST_KEEP_ROOTS=1`. `hostStrict` launches with no debugging flag and waits up to `RECNRUN_HOST_GESTURE_TIMEOUT_MS` for the owner's `Load unpacked`; its tests are skipped unless `RECNRUN_HOST_GESTURE=1`.
- `tests/browser/fixtures/x-display.ts` reads browser UI
  with no CDP handle on the container's Xvfb display (window titles and `clickAt` with xdotool, the display with scrot) and throws unless `RECNRUN_TEST_CONTAINER=1`, so it never acts on a host screen; pass xdotool no `--long` options, which the harness scan reads as Chrome flags.
- **Calling CDP.** Send commands only as `<session>.send("Domain.method", params)` with the method as a string literal at the call site; `tests/observer-allowlist.test.ts` scans `tests/browser`, `tests/experiments`, and `tests/host` and fails on a command outside its allowlist, on `ServiceWorker.*`, `Fetch.*`, `Debugger.*`, `Emulation.*`, `Storage.clear*`, `Target.setAutoAttach`, `Page.addScriptToEvaluateOnNewDocument`, `Page.setBypassCSP`, cookie writes, header or user-agent overrides, on raw `Runtime.evaluate` outside `tests/browser/fixtures/cdp-client.ts`, on Playwright calls that rewrite or inject into the page (`route`, `addInitScript`, `addScriptTag`, `setContent`, `addCookies`, `setOffline`, and the rest of its list), and on launch flags outside its list (any `--disable-*`, and `--load-extension`). `cdp-client.ts` connects only to a `ws://` endpoint on the loopback. Adding a command means adding it to the allowlist with its reason.

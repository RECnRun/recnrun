# Improvement plan

Review of `master` at `e6b0f2b` (2026-10-25, after PR #10 "incognito banner" and PR #11 "frame route echo"). It covers architecture, large modules and functions, dependencies, and the parameters of the `vp run verify` gates, and ranks the work in three tiers:

- **Must**: a correctness or security gap, or a gate that does not guard what the docs say it guards.
- **Should**: structure that will cost more once M1 (recording) starts, or a gate that wastes time.
- **Nice to have**: cleanups with a clear benefit and no urgency.

Each item has an id (`M`, `S`, `N`), a size (S: under an hour; M: half a day; L: a day or more), and an acceptance check. Items are independent unless they say otherwise. Delete an item from this file once it ships, and move the decision it records into the doc it belongs to.

## Findings

### Architecture

- **A1. Session control has four owners.** The background creates the session (`background/session-requests.ts`); the pages write pause and stop straight to `storage.session` (`views/recording.ts`); "who controls" lives in a Web Lock plus a `BroadcastChannel` (`messaging/view-locks.ts`), a closure in `dashboard/start.tsx`, and the `pagehide` → `panel-closed` → `return-to-dashboard` chain through `content/panel-window.ts`. The `extension-dashboard-isolated` rule ("starts a session through the background") covers creation only. M1 needs "a session exists iff capture runs", which only the background can enforce.
- **A2. Two `runtime.onMessage` listeners, two sender policies.** `background/handler.ts` accepts any sender with the extension id; `background/session-requests.ts` accepts only extension pages. Each parses every message with its own schema and returns `false` for the other's. A third message family (recorder events) would repeat both, and a type matched by two schemas would reply twice.
- **A3. Shared types have no home.** `SessionStore` (`background/session-requests.ts`) and `RecordingStore` (`views/recording.ts`) are the same port, declared twice because the layering rules let neither import the other. `views/recording.ts` mixes pure session math (`elapsedSeconds`, `toggled`, `formatElapsed`) with Preact hooks; `.claude/rules/domain.md` assigns "data shapes and pure helpers" to `@recnrun/domain`. `messaging/view-locks.ts` is runtime behavior imported by `dashboard/` and `views/`, not a message schema, yet it lives beside the protocols.
- **A4. Capabilities travel as optional props.** `tabs?`, `incognito?`, and `holdSitePorts?` on `DashboardData` mean "absent outside the extension" and are threaded `DashboardData` → `SessionSetup` → `TabList` → `IncognitoControl`; `TabList` renders the incognito settings banner inside the tabs aside and gates the whole list on `useIncognitoAccess`; `IncognitoAccess.openSettings` (a `chrome://extensions` navigation) lives in `tabs/open-tabs.ts`, which the `extension-tabs-is-model` rule defines as the tab model.
- **A5. The frame channel is parsed message by message.** PR #11 brought the `recnrun-frame` channel to six message types. The content script's one listener tests `NavigateMessageSchema` then `LocationMessageSchema` in sequence (`content/dashboard-frame.ts`); the dashboard page registers two `message` listeners (`dashboard/router.ts` for `route`, `controlFrom` in `dashboard/start.tsx` for `panel-closed`), each re-checking source and origin. Both page starters also repeat the ancestor guard: `dashboard/start.tsx` 77–84 and `session/start.tsx` 15–22 are the repository's only jscpd clone.
- **A6. `tests/e2e` imports packages by relative path.** `../../packages/domain/tests/fixtures.ts` in three specs and `../../../packages/domain/src/index.ts` in `fixtures/extension.ts`, because `tests/` belongs to no workspace. `.claude/rules/tests.md` and `docs/ARCHITECTURE.md` tell authors to import `@recnrun/domain/testing`, which does not resolve there, and the `../` lint ban covers only `apps/*`.
- **A7. The content script's resources have no owner.** `content/start.ts` wires the frame (`dashboard-frame.ts`), the PiP window (`panel-window.ts`), and the orphan watch (`orphan-watch.ts`) side by side; the orphan handler removes the frame but leaves a PiP window the same script opened.

### Large modules and functions

No module or function breaks a cap, and the caps are already strict. The spots closest to them:

- `dashboard/Dashboard.tsx` (181 lines) holds nine components plus the `navigate` wrapper: snapshot loading, routing links, empty states, workspace grouping, list, detail, and the page shell.
- `dashboard/TabList.tsx` (136 lines) combines four hooks (`useBrowserTabs`, `useRecording`, `useLockHeld`, `useIncognitoAccess`) with three components and the error state.
- `views/use-browser-tabs.ts`: one 35-line effect with four mutable flags (`live`, `reading`, `again`, `shown`) implementing read coalescing; its correctness is tested only through components.
- `messaging/view-locks.ts` `watchLock`: a recursive async check over `navigator.locks` and a `BroadcastChannel`.
- `scripts/test-container.mjs` `startTests` and `run`: around 40 lines each with interrupt, artifact, and exit-code handling interleaved.

### Correctness and security

- **C1. Session requests cannot surface an error.** `startSession` swallows an unreadable stored session (`store.read().catch(() => null)`) and overwrites it, while every view's `useRecording` shows "does not match the current schema" for the same value; `createSessionListener` never replies (`void done.catch(() => {})`, returns `false`), so a failed write leaves the PiP window blank and the control lock held. `.claude/rules/extension.md` says invalid stored data is an error reply, never a partial result.
- **C2. The manifest guard checks less than the docs claim.** `apps/extension/scripts/manifest.checks.mjs` asserts `permissions`, `host_permissions`, `externally_connectable`, `commands`, and `action.default_popup`. It never asserts `optional_permissions`, `optional_host_permissions`, `content_security_policy`, or the content script's `all_frames`, `match_about_blank`, and `match_origin_as_fallback`, though the "Recording (not built)" section relies on it.
- **C3. "The content script never touches storage" is a folder rule only.** `extension-content-not-to-storage` forbids `src/content` → `src/storage`; nothing forbids `import { storage } from "wxt/utils/storage"` or `browser.storage.*` through the `wxt/browser` import `content/start.ts` already has. ARCHITECTURE.md's "cannot read storage itself" overstates it: with the `storage` permission, content scripts can.
- **C4. `PathSchema` admits protocol-relative paths.** `v.startsWith("/")` accepts `//evil.example/x`, while ARCHITECTURE.md says the frames accept "only paths that start with `/`" as the guard against navigation. Since PR #11 only a `navigate` message reaches `history.pushState`, and the dashboard sends it only for its own `recordingPath(id)` links, so a forged `route` with `//` now changes the dashboard's route state and nothing else. What remains is a schema that admits what the docs say it rejects, and no test for `//` (`frame.browser.test.tsx` covers only `https://evil.example/`).
- **C5. One frame guard has no negative test.** `mountDashboardFrame`'s listener checks source and origin, but no test posts a forged `navigate` or `location` to it; the dashboard router and the PiP listeners do have such tests.
- **C6. `start-session` for a closed tab stores a session.** `startSession` writes before `focus`; when `tabs.update` rejects, the session stays, the dashboard shows a "Closed tab" item with a running timer, and the PiP shows "The recorded tab was closed". The unit test asserts only `answered === false`.
- **C7. `error instanceof Error ? error.message : String(error)` appears four times** (`background/handler.ts`, `dashboard/Dashboard.tsx`, `views/recording.ts` as `errorText`, `packages/bridge/src/host.ts`).
- **C8. `extension-state.ts` branches are half covered**: the unmount-before-detect path is untested.

### Dependencies and configuration

- **D1.** Catalog pins are coherent; the `vite` → `@voidzero-dev/vite-plus-core` override is documented. `@types/node` must stay on 24 to match Node 24.21 in `Dockerfile.tests`.
- **D2.** `engines.node` is `>=22.18.0` while the only tested runtime is 24.21.0 (Docker, `VP_NODE_VERSION`).
- **D3.** `apps/extension/vitest.browser.config.ts` and `apps/website/vitest.browser.config.ts` are identical except for the project name and the screenshot folder.
- **D4.** `tsconfig.json` (root), `apps/website`, `packages/bridge`, and `packages/domain` each declare their own compiler options; only the website has `noFallthroughCasesInSwitch`, the root lacks `noUncheckedIndexedAccess` and `verbatimModuleSyntax`, and the extension inherits them from `.wxt/tsconfig.json`.
- **D5.** `pnpm-workspace.yaml` `minimumReleaseAgeExclude` names `dependency-cruiser@18.7.0` and `knip@6.42.1`, which are past the release age now.
- **D6.** `apps/extension/wxt.config.ts` imports `../../scripts/dev-chrome.ts` (PR #10), which pulls `@playwright/test` from the root into the extension's dev server. It is the only app file that reaches outside its workspace; dependency-cruiser excludes configs, so no rule sees it, and `apps/extension/package.json` does not list the dependency it now uses.

### Verify gates

- **G1. Coverage thresholds are 13 to 18 points below reality.** A regression from 95 % to 81 % of statements would pass.
- **G2. Coverage has a ratio but no denominator.** `coverage.include` is a repo-relative glob; a filtered run or a renamed folder measures fewer files and still reports green.
- **G3. Knip runs a subset.** `--include files,exports,dependencies,unlisted` skips `types`, `nsExports`, `duplicates`, `enumMembers`, `classMembers`, and `unresolved`; the defaults pass today, so the narrowing buys nothing.
- **G4. jscpd threshold 4 % against 0.35 % measured.** The one clone is A5.
- **G5. `verify:local` runs unit and component tests twice**: once in `test:local`, again under `test:coverage:local`, which runs every Vitest project. In Docker that is minutes per run.
- **G6. Lint has room for a few cheap rules**: `max-statements`, `sonarjs/no-identical-functions`, `sonarjs/no-duplicate-string` (C7), and a restricted-import rule for C3.
- **G7.** Vitest reports "at least ~5.5 s faster with `isolate: false`" on a 13 s run.

## Method

Two review agents read the code at `7d93ca1` against the documented invariants (`docs/ARCHITECTURE.md`, `.claude/rules/*.md`) and for root causes; every finding they returned was checked against the source, then re-checked at `e6b0f2b` after PRs #10 and #11 merged: PR #11 removed the navigation harm behind C4 (now S11) and gave A5 its sixth message type; nothing else changed. The gate numbers above come from running the gates on the host at `e6b0f2b`. Correctness findings C1 to C6 are design gaps, not observed failures: no gate fails and no test is red today.

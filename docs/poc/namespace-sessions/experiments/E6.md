## Hypotheses and verdicts

The hypotheses of P1.5: (a) the wrapper's first statement imports a slot that a session DNR rule (or Route B) selects, so the persisted script never names a session, the script cache does not freeze the slot, and an offline start still resolves it; (b) `registration.update()` re-resolves the slot per switch and the extension waits for `activated`; (c) dedicated and shared workers select the slot with a synchronous XHR to a DNR-redirected URL. Also measured: the MV3 background suspended and resumed between two starts, and a Chrome restart on the same profile. A sample passes when the worker that starts after the switch opens its IndexedDB database as `__rec:<new slot>:<store>`, or when its own requests carry `__rec=<new slot>` (the oracle needs no network, so E5's Local Network Access block does not void it). A start that still runs as the old slot, or that opened only the old slot's database, is `stale` and counts in `lateAttaches`. `switchMs` is the time `declarativeNetRequest.updateSessionRules` took; `restartMs` is the time from the restarting navigation to its commit or to the harness giving up after 20 s.

## How it runs

The isolator owns every `chrome.debugger` and DNR call. `apps/isolator/src/background/selection/` exposes `recnrunSelection` on the isolator's service worker: `select({ slot, origins })` replaces its session rules (ids 6100 to 6199) with redirects of `chrome-extension://<id>/ns/current.js` and of `<origin>/recnrun/current.js` on each loopback origin to the web-accessible `ns/slot-<k>.js` that Route C already ships; `clear`, `rules`, `status`, and `suspend` (which attaches `chrome.debugger` to the background's own worker target and sends `Target.closeTarget`, after detaching a session a previous instance left there). `apps/isolator/src/background/route-b/select.ts` builds the wrappers, none of which names a session:

- `extension-import`: `importScripts("chrome-extension://<id>/ns/current.js", "chrome-extension://<id>/route-c.js")`.
- `app-import`: `importScripts("/recnrun/current.js", "chrome-extension://<id>/route-c.js")`, the first URL redirected by the session rule.
- `fetch-import`: `importScripts("/recnrun/fetched.js")`, which Route B fulfills with `withMarker(<armed marker>)` when Chrome fetches it.
- `sync-xhr` (dedicated and shared workers): a synchronous `XMLHttpRequest` for `/recnrun/current.js`, the marker read from the redirected slot file, then the bootstrap.

Route B (E5's `recnrunRouteB.arm`) arms a tab with the selection; a service worker's main script is wrapped on the worker session, and a dedicated or shared worker's script, which Chrome 156 pauses on the tab session as `Other` (fixed in 9050f17), is wrapped there.

The spec only drives pages and reads results, through the shared `page-loads.ts` and E5's `e5-loads.ts`. A service-worker switch (`e6-loads.ts`): select slot `before`, register `sw-main.js?variant=classic` from an armed tab, read the stores, switch to slot `after` (at once, or under `switch-early` when the ledger first shows the script's fetch), wait until the registration has no installing or waiting version, close the tab, stop every worker target, open `storage.html` under the scope in a new tab armed for `after` with `Network.enable` on worker sessions, and read the stores, the ledger, and Route B's journal. A workers switch loads `workers.html?type=classic` under `before`, closes it and waits until no shared worker is listed, switches, and loads it again. The paths in `e6-paths.ts`: `update` re-arms the tab for the new slot and evaluates `registration.update()` in the page through the isolator; `offline` stops the worker, cuts the fixture with `POST /__network?mode=offline`, opens the scope page, reads the journal and stores before restoring the network; `suspend` runs a workers switch with `recnrunSelection.suspend()` between the two loads, waits until `getTargets()` no longer lists the background, and opens a tab, whose `tabs.onCreated` wakes it; `restart` installs under slot 4 in a Chrome on a temporary profile, closes Chrome, relaunches it on the same `userDataDir` (`loadUnpackedOverCdp` accepts one), and restarts the worker. The pure evaluation lives in `tests/experiments/e6-samples.ts`, tested by `tests/e6-samples.test.ts`; `samples.json` keeps every sample, its outcome, the suspension records, and the journals.

## Observations

- **Both redirected `importScripts` variants fail at the first registration.** In 4 of 4 samples per run (`extension-import` and `app-import`, 2 each) `register()` rejected with `ServiceWorker script evaluation failed`; no worker attached to Route B and no `/recnrun/current.js` request reached the fixture. Inferred from Chromium's service-worker script loader, which refuses a script response behind a redirect for imported scripts too, and from the scheme check on imported scripts: a DNR redirect to a `chrome-extension://` slot cannot serve a service worker's `importScripts`, whichever URL the wrapper names. The exact cause is not in the evidence; Chrome reports only the evaluation failure.
- **`fetch-import` installs and runs the armed slot.** Every first registration opened `__rec:slot-4:fixture-sw` and its first paint carried `__rec=slot-4`. The ledger shows `/recnrun/fetched.js` fetched once per installation and never again: 2 in the switch test (2 installations) and 10 in the paths test (5 `update` and 5 `offline` installations), none at a restart, an offline start, or `update()`.
- **The script cache freezes the slot.** With the fixture offline, after a switch from slot 4 to slot 5, the stopped worker started again from storage in 5 of 5 (the tab showed `Fixture offline`; the restart's waiting target closed before release with `{"code":-32000,"message":"Inspected target navigated or closed"}`, as in E5), and IndexedDB held only `__rec:slot-4:fixture-sw`, with no `__rec:slot-5:fixture-sw`. In run B one restarted worker's blocked `/me` showed `&__rec=slot-4` (`net::ERR_FAILED`, `LocalNetworkAccessPermissionDenied`); the other requests failed without a URL. Inferred: the imported `/recnrun/fetched.js` is part of the installed version and is served from the script cache, so the slot it set at installation is the slot of every later start.
- **The restarting navigation runs an update check that installs the unwrapped original.** In each of the 4 fetch-import switch samples of runs B and C, the ledger shows a second `/sw-main.js?variant=classic` fetch (`serviceworker` destination) 130 to 182 ms after the first, followed at once by `/me?from=%2Fsw-main.js%3Fvariant%3Dclassic` without a marker. The harness counted one script fetch up to the restart's checkpoint in every sample, so the second came after the restart began. The restarted worker attached waiting, its `/me` left without `__rec`, and IndexedDB gained the unprefixed `fixture-sw` (`unprefixedAfter` 2). Inferred: Chrome checks for an update when a navigation enters the scope; as E5 found, that check is not interceptable and compares the original bytes with the stored wrapped ones, so it installs the original.
- **The restart after that update stalls 300 s.** The navigation to `storage.html` did not commit within 20 s in 2 of 2 fetch-import samples per run (`restartMs` 20,004 to 20,015). The ledger shows its document request reaching the fixture 300.0 s after the update's script fetch in all 4 samples of runs B and C. A restart from an unarmed tab stalled the same way in an exploration run, and two `sw-main.js` targets were listed while it stalled. Inferred, not proven: the navigation's fetch event waits on a worker that never answers until Chromium's 5-minute service-worker request timeout falls back to the network; Playwright's auto-attached `connectOverCDP` session (E4's confound) may be what holds that worker. Each such sample costs 300 s, which is why the switch test takes only 2 samples per service-worker variant.
- **`update()` re-resolves nothing.** After `update()` with slot 5 selected, Chrome reported `updatefound` with an installing version in 5 of 5, which activated after 533 ms (p50, max 2,429), and IndexedDB gained the unprefixed `fixture-sw` in 5 of 5: the new version is the unwrapped original (E5), and `/recnrun/fetched.js` was not fetched. Waiting for `activated` therefore activates a version without any selection.
- **Dedicated and shared workers follow the switch in 100 of 100.** The synchronous XHR to `/recnrun/current.js` returned the slot the session rule pointed at when the worker started: every second load opened `__rec:slot-7:fixture-dedicated` and `__rec:slot-7:fixture-shared` after a first load under slot 6, at baseline and under all seven stress conditions, with `updateSessionRules` taking 0.4 ms (p50) to 4.2 ms (max, `cpu-load`). Route B fulfilled `worker.js` and `shared-worker.js` on the tab session (`Other`, `sync-xhr` wrapper) in every load. The workers' own `/me` failed (`TypeError: Failed to fetch` in 98 first-load reports, `Error: no report within 10 s` in 2); inferred to be E5's Local Network Access block of a fulfilled worker, which the database oracle does not depend on.
- **A suspended background keeps the selection.** With d2288d0, `recnrunSelection.suspend()` stopped the isolator's background in 3 of 3 (`getTargets()` stopped listing it), the next tab woke it through `tabs.onCreated` with a new `performance.timeOrigin`, the session rules 6100 and 6101 were still there, and the workers opened the new slot's databases in 6 of 6. Before the fix only the first suspension worked: Chrome kept the extension attached to the background's worker target, whose id survives the stop, and each later `chrome.debugger.attach` failed with `Another debugger is already attached to the target with id: F5CB55E3A791EE15E7E33705715F9912.`
- **Session rules do not survive a Chrome restart; the installed slot does.** After relaunching Chrome on the same profile, `recnrunSelection.rules()` returned 0 rules in every run, and the restarted fetch-import worker still ran as slot 4 (`/me`, `__marker?name=storage:start`, and `favicon.ico` carried `__rec=slot-4`), 33 to 64 ms after the navigation started (runs A to C). The slot came from the script cache, not from a rule.

## Not covered

A real change of the app's script bytes (the fixture is frozen), a Chrome restart after a switch (the rules are gone after a relaunch and the slot is frozen in the cache, so the restart test only checks that the installed slot survives), more than 2 samples per service-worker variant (each stalled restart costs about 300 s; every variant fails before repetition could change its verdict), service-worker selection with a synchronous XHR (service workers cannot issue one), any Local Network Access grant (an owner decision from E5), runs without Playwright's `connectOverCDP` session attached (the harness needs it; it may hold the stalled restart), the reason Chrome refuses the redirected `importScripts` beyond its evaluation error, and Chrome on a desktop or outside Linux.

## Reproducing

`vp run test:experiments -- tests/experiments/E6-route-b-selection.spec.ts` appends the six verdicts to `.artifacts/evidence/<run>/verdicts.json`, merges `e6Selection` into `.artifacts/evidence/<run>/capabilities.json`, and writes `samples.json` (and the ledger) under `.artifacts/evidence/<run>/E6-route-b-selection/<test>/` (inside `.artifacts/docker/<run>/` for a Docker run). `vp run test:stress -- --iterations 7` runs the order-critical test once under each stress condition.

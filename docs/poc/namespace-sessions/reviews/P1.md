## Findings

1. **Major — Routes A and B can operate on non-loopback targets.**  
   [route-a/engine.ts:126](../../../../apps/isolator/src/background/route-a/engine.ts#L126), [route-b/engine.ts:132](../../../../apps/isolator/src/background/route-b/engine.ts#L132).

   Route A checks only that the target exists before calling `api.attach()` and `bootstrap()`. Route B’s `stopWorker()` attaches and closes the supplied target without checking its URL. Their tab arming and attached-worker handlers also lack loopback checks. The debugger permission needs no host permission, so the manifest’s localhost entries do not enforce this boundary.

   An in-memory control accepted an `https://example.com/` tab and worker, sending `Runtime.evaluate`, `Fetch.enable`, and `Target.closeTarget`. **Fix:** validate target type and loopback origin before direct operations, enforce the boundary for attached children and intercepted responses, and handle navigation away from an armed loopback tab. Add negative controls that assert no modifying command reaches an outside target.

2. **Major — E6 can pass without a successful start after the switch.**  
   [e6-samples.ts:80](../../../../tests/experiments/e6-samples.ts#L80).

   The evaluator returns success before checking contradictory observations:

   ```ts
   if (has(second, nameOf(sample.after, store)) || running.includes(sample.after)) return undefined;
   ```

   A destination database can already exist from the first load during an early switch, or from previous warm loads. Its presence therefore does not prove the second worker started under that slot. A control containing the destination database, `started: false`, `stalled: true`, and an old running marker returned `reasons: []` and `fresh: 1`. Unprefixed storage is also ignored by this early return.

   **Fix:** require evidence attributable to the second start, reject contradictory stale or unmarked execution, and check startup failure before accepting stored names. Add negative controls for existing destination stores followed by failed, stalled, or stale starts.

3. **Major — Stop rules become unremovable after background suspension.**  
   [stop/engine.ts:32](../../../../apps/isolator/src/background/stop/engine.ts#L32), [stop/engine.ts:81](../../../../apps/isolator/src/background/stop/engine.ts#L81).

   Rule ownership exists only in memory:

   ```ts
   readonly #rules = new Set<number>();
   #nextRule = 1;
   // ...
   await unblock(recorder, [...this.#rules]);
   ```

   DNR session rules survive an extension background restart. Recreating the engine therefore loses the IDs needed for cleanup and resets allocation onto existing IDs. A control that blocked through one engine and unblocked through a replacement returned `removed: []`, leaving rule 1 installed.

   **Fix:** reserve an owned ID range and recover installed rules through `getSessionRules()`, or persist and reconcile ownership. Record successful installation before subsequent eviction work can fail. Test cleanup and allocation across engine recreation.

4. **Major — The stress gate accepts missing or contradictory evidence.**  
   [test-stress.mjs:88](../../../../scripts/test-stress.mjs#L88), [test-stress.mjs:126](../../../../scripts/test-stress.mjs#L126), [test-stress.mjs:217](../../../../scripts/test-stress.mjs#L217).

   Missing evidence is treated as an empty successful result:

   ```js
   if (error.code === "ENOENT") return { verdicts: [] };
   ```

   Consequently, listed tests that are skipped or stop writing verdicts can leave the runner green. Separately, `lateAttaches` is only accumulated; a passing verdict with a positive count never creates a failure. E8’s `counts.firstEffectBeforeMarker` is not read at all.

   In-memory controls produced no failed iterations for empty verdicts, a passing verdict with `lateAttaches: 1`, and an E8 verdict with `counts.firstEffectBeforeMarker: 1`. **Fix:** require expected evidence for every iteration, reject missing observations, normalize leak counters, and fail a claimed passing hypothesis with any late effect. Cover all three controls in the runner checks.

5. **Major — The decision mapping counts supporting measurements as capability passes.**  
   [decide-mapping.mjs:73](../../../../scripts/decide-mapping.mjs#L73), [decide-mapping.mjs:85](../../../../scripts/decide-mapping.mjs#L85).

   These rows feed capability totals:

   ```js
   ["E4/debugger-pause", "a pause holds the worker without stopping it"][
     ("E5/imports", "importScripts and static imports pause on the worker session")
   ];
   ```

   E4’s pause hypothesis can pass with `restarted: false` and `observed: false`; a control confirmed exactly that. It does not demonstrate `serviceWorker.cold`. E5’s imports evaluator checks interception, without proving first-statement isolation, yet contributes a pass to `serviceWorker.first`.

   **Fix:** retain these as supporting or diagnostic measurements excluded from capability pass counts. Populate those cells from hypotheses that prove the capability’s required effects, and add mapping checks for successful prerequisites alongside failed capability proofs.

6. **Major — The report’s recommendation prose contradicts the committed E8 evidence.**  
   [REPORT-P1.md:24](../../../../docs/poc/namespace-sessions/experiments/REPORT-P1.md), [REPORT-P1.md:140](../../../../docs/poc/namespace-sessions/experiments/REPORT-P1.md).

   The report says “no run without it exists,” lists a run without Playwright CDP as uncovered, and concludes Route A “cannot reach a restart before its first statement.” However, its generated table includes E8, whose committed verdicts report 20/20 cold starts and 10/10 marked restarts through managed-policy installation without CDP.

   The prose also attributes the evidence to the earlier 70-verdict run while the table now contains 74 verdicts. This can materially misdirect the owner’s route decision. **Fix:** document E8’s separate provenance, rewrite the conclusions around the child-session fix, and distinguish historical failures from current behavior. Rerun older hypotheses at HEAD if their numbers remain claims about the current implementation.

7. **Minor — `net-delay` does not delay the operation being stressed.**  
   [e3-loads.ts:156](../../../../tests/experiments/e3-loads.ts#L156), [e6-loads.ts:91](../../../../tests/experiments/e6-loads.ts#L91).

   Both implementations finish an unrelated slow navigation before arming or beginning the measured load:

   ```ts
   if (CONDITION === "net-delay") await page.goto(`${API}/slow?ms=300`);
   ```

   This adds preparation time without delaying worker scripts, selection requests, or the critical interval. The condition name therefore overstates the latency coverage.

   **Fix:** introduce a plan-compliant fixture delay affecting the measured requests and verify its timing. Until then, rename this condition and explicitly record network-latency stress as untested.

8. **Minor — The event cap invalidates E8’s trace checkpoints.**  
   [e8-loads.ts:85](../../../../tests/experiments/e8-loads.ts#L85), [route-a/engine.ts:242](../../../../apps/isolator/src/background/route-a/engine.ts#L242).

   E8 checkpoints the array length and later uses:

   ```ts
   events: (journal?.routeA.events ?? []).slice(from.events);
   ```

   Route A now shifts old events once the array reaches 200. After saturation, a checkpoint of 200 causes every subsequent trace to be empty; crossing the limit also produces incorrect slices. A control recorded a new event and `eventsDropped: 1`, while E8’s slicing returned `[]`.

   **Fix:** checkpoint a monotonic event sequence, or account for the cumulative dropped count. Include that metadata in the harness journal type and report when a requested trace has been truncated.

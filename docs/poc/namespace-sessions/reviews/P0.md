## Findings

1. **Major — E1 can report functional failures as passing capabilities.**  
   [apps/isolator/src/background/probes/workers.ts:109](../../../../apps/isolator/src/background/probes/workers.ts#L109), lines 109–140; [domains.ts:108](../../../../apps/isolator/src/background/probes/domains.ts#L108).

   The probes return observations without checking them:

   ```ts
   return { pausedEventArrived };
   return { success: success ?? null, listedAfter };
   ```

   `attempt()` marks any normal return `allowed`. A controlled fake produced `allowed` for all three cases: cookie write returned `success: false`, no pause event arrived, and closing the worker returned `success: false` while it remained listed. Aggregation also preserves only the first sample’s detail, potentially hiding later failures.

   **Fix:** reject failed effect checks and preserve each sample’s observations. If command acceptance is intentionally a separate measurement, record it separately from whether pausing, closing, or writing cookies worked. Add negative controls for these cases.

2. **Major — The observer allowlist misses ordinary page-instrumentation APIs.**  
   [tests/harness-scan.ts:29](../../../../tests/harness-scan.ts#L29), lines 29–49 and 90–100.

   The scanner relies on `PLAYWRIGHT_FORBIDDEN`, which omits `addScriptTag` and `setContent`. Both controlled examples returned **zero scan sites**:

   ```ts
   await page.addScriptTag({ content: "window.__injected = true" });
   await page.setContent("<script>window.__injected = true</script>");
   ```

   Consequently, the P0.7 gate accepts harness code that injects application behavior, contrary to decision 5.

   **Fix:** cover these APIs and add failing scanner controls. Also constrain the permitted `Browser.setPermission` exception to notification denial: currently its name alone is allowed, including calls that grant permissions.

3. **Major — CDP requests never settle when their transport disappears.**  
   [tests/browser/fixtures/cdp-client.ts:38](../../../../tests/browser/fixtures/cdp-client.ts#L38), lines 38–48, 53–85.

   Requests remain in `pending` until a matching reply arrives; `close` merely closes the underlying transport:

   ```ts
   pending.set(id, { resolve: ..., reject: ... });
   // ...
   close,
   ```

   Neither WebSocket closure nor pipe EOF rejects pending requests, and commands have no deadline. An in-memory pipe control confirmed that a request remained pending after EOF and `client.close()`.

   A Chrome crash or terminated extension worker can therefore strand E0/E1 until Playwright’s outer timeout, preventing loader cleanup and verdict recording. The `timeoutMs` argument to `evaluateInServiceWorker` only bounds target polling.

   **Fix:** reject all pending requests on close/error/EOF, reject sends after closure, and add command deadlines. Test transport loss during attachment, evaluation, and detachment.

4. **Major — E1 drops the diagnostic label when the loader falls back to Chromium.**  
   [tests/experiments/E1-debugger-capabilities.spec.ts:159](../../../../tests/experiments/E1-debugger-capabilities.spec.ts#L159), lines 159–160 and 211–218.

   E1 records:

   ```ts
   aggregate(id, results, extension.chrome.version);
   await appendVerdict(verdict);
   ```

   It never propagates `extension.label`. The loader explicitly supports a `diagnostic` Chromium fallback, but E1’s resulting verdicts and debugger capability entries carry no such label. This breaks the machine-readable distinction required by decisions 3 and 7 and can let diagnostic results enter a later GO decision.

   **Fix:** propagate the actual browser label and load method into every E1 verdict and capability record, render the label in `CAPABILITIES.md`, and test the fallback path.

5. **Major — Saved ledger evidence discards most of each fixture test.**  
   [tests/browser/fixture.spec.ts:42](../../../../tests/browser/fixture.spec.ts#L42), lines 42–44 and 97–106.

   Every route report starts with:

   ```ts
   await control("/__ledger/reset");
   ```

   The observer collects the ledger only in `afterEach`. Thus the storage/workers/sockets test saves only its final sockets segment, and the service-worker test loses the earlier variants. Existing exported evidence confirms this: the former has no worker first-request entries; the latter retains only the dynamic variant. Conversely, the popup test never resets the ledger and inherits entries from the preceding test.

   **Fix:** reset once before each test and use sequence checkpoints for individual assertions, preserving the complete ledger until collection. Assert that the saved file contains every exercised worker variant and excludes preceding-test activity.

6. **Minor — The egress test does not exercise E1’s probe entrypoint or its browser-mediated requests.**  
   [apps/isolator/tests/egress.test.ts:93](../../../../apps/isolator/tests/egress.test.ts#L93), lines 93–108.

   The test calls `startBackground`, installation/startup listeners, and `GET_SELF`, then checks:

   ```ts
   expect(egress).toEqual([]);
   ```

   It never invokes `recnrunProbes.run`. Moreover, the global `fetch` shim cannot observe requests initiated in a debuggee through `Runtime.evaluate`, such as the iframe created by the auto-attach probe. The advertised egress guarantee therefore does not cover the principal new runtime path.

   **Fix:** exercise the probe entrypoint under the guard, validate supplied probe URLs as loopback before issuing commands, and add a controlled non-loopback iframe/navigation case that must fail before Chrome receives it.

7. **Minor — `docs:check` deliberately accepts broken same-document anchors.**  
   [scripts/check-docs.mjs:84](../../../../scripts/check-docs.mjs#L84), lines 84–85.

   ```js
   if (SCHEME.test(target) || target.startsWith("#")) return undefined;
   ```

   This accepts `[section](#nonexistent)` unconditionally; the unit test explicitly expects `#nowhere` to pass. That contradicts P0.1 and `AGENTS.md`’s promise that every relative Markdown link and anchor resolves.

   **Fix:** resolve fragment-only links against the current file and validate its anchors. Replace that positive expectation with valid-anchor and missing-anchor controls.

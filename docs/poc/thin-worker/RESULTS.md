## W1 lab run (`W.rtc`)

Google Chrome 157.0.8103.38 on Linux (Docker image `sha256:ab532ec9e844`), run `2026-11-06T22-18-09.019Z-886ddf42-a879-4c38-b371-798de8a1d80f`, `vp run lab:web-master` (`tests/lab/web-master/w-rtc.spec.ts`), both variants passed. Fast track: the harness relays the SDP; no cell exercises the folder signalling or its latency (Phase 1).

- **Setup.** The master is a normal root with no extension, opened at `https://recnrun.test:<port>` (secure context, valid chain, no certificate flag; master flags: `--user-data-dir`, `--remote-debugging-port=0` to drive it, `--no-first-run`, `--no-sandbox` for root in the container). Two workers on roots of their own, one headed and one `--headless`, each an unpacked MV3 extension whose offscreen document (`WEB_RTC`) answers with `iceServers: []`.
- **Deviation.** The test CA is trusted through the managed `CACertificates` policy, not Chrome's NSS store: the image has no `certutil`, and the policy is the documented trust path that needs no flag. `recnrun.test` maps to `127.0.0.1` through the runner's `--add-host`.
- **Pass.** For each worker: the offer's only host candidate is an mDNS `.local` name, kept in the SDP; the data channel opened; the page verified the worker's ECDSA P-256 signature, under the key pinned before the offer, over a nonce and both DTLS fingerprints; 100 ping round trips.
- **Selected pairs** (`getStats`): every link is `host` (the page's `.local`, address hidden in stats) to `host` `172.21.0.2` (the worker's plain IP), UDP. The worker offscreen documents offer plain IPs, as the plan expected.
- **Timings** (default / public): answer applied to channel open 3.2 / 2.8 ms (headed) and 7.9 / 6.3 ms (headless); 100 pings 27.9 / 29.2 ms and 36.5 / 35.1 ms; two links from the first offer 586 / 548 ms.
- **Variant `public`.** `--ip-address-space-overrides=127.0.0.1:<stand-in port>=public` scoped to the stand-in's endpoint: CDP reports the document and subresource as `Public` and the page's `initiatorIPAddressSpace` as `Public` (`Loopback` in the default variant), with `localNetworkAccessRequestPolicy: PermissionBlock` in both. The link to the worker's private address still came up with no prompt; `navigator.permissions.query({ name: "local-network-access" })` read `prompt` before and after, so WebRTC did not consult it on this revision `[unsure]` whether a later revision gates WebRTC. The restart repeat is moot with no prompt.
- **Prompts.** None on the display in either variant (`display-default.png`, `display-public.png`).
- **Negative control.** The same spec with the answer's DTLS fingerprint changed by one byte before the page applied it failed: `Error: channel headed did not open` after 20 s (scratch worktree, not committed).
- **Review follow-up** (commit `c1dd54db`, [PW review](reviews/PW.md) finding 8). The spec now asserts Chrome's address-space classification of the page and its responses (`Public` with the override, `Loopback` without; the other value must be absent). A wrong-pinned-key control, with valid SDP, DTLS, channel, 100 pings, and a succeeded pair, is rejected by the page as `proof-not-signed-by-pinned-key`. Latency, LNA, and prompt observations stay recorded, not asserted. `[unsure]` The control pins a wrong key on the page side; a worker that signs with another key is not exercised.
- **Not covered.** macOS (M-TW.13), the real origin (M-TW.12), and the folder signalling (Phase 1).

  The grant then held with no gesture across a page reload, a further page close and reopen, and two restarts (`tab-reopen-open.png`, `tab-restart-1-open.png`, `tab-restart-2-open.png`).

- **Residual risk.** Any code the origin serves, a compromised deploy or a supply-chain change of recnrun.com included, can use the stored key with no owner action and no visible sign: `extractable: false` stops export, not `sign()`. The lab shows that jobs naming an origin outside the allowlist, in the envelope or in a `navigate` argument, are refused; it does not confine effects or reads (no destination, redirect, or stale-document check, no network guard; [PW review](reviews/PW.md) finding 5). Within that, it can navigate, type, click, wait, and read up to 16 KiB per read and 64 KiB per job (UTF-8 bytes), up to 32 ops, one job at a time, and it can read the outcomes of earlier jobs through `JOB_STATUS`. What bounds it: the closed op set and its argument caps, the allowlist that only the onboarding script writes (no page message changes it), the per-job caps, the ledger (no replay of an accepted mutation), and the pin, which fails closed when the key is lost. A key the owner revokes is replaced only through the onboarding script. Compared with the Store master, the trusted code base grows from a reviewed extension package to whatever the origin serves at each visit.
- **Review follow-up** (commits `59cbf740`, `c192f6e4`, [PW review](reviews/PW.md) findings 1–4 and 12; `tests/lab/web-master/w-admission.spec.ts`, 9 tests, red 8 of 8 against the old worker; full lab run `2026-11-07T07-57-50.325Z-13178a3d-d7c7-437c-bc36-85772e0652d9`, 28 passed). The worker admits one job at a time through a single serialized queue. A concurrent duplicate of the same job returns the ledger status (`REPLAYED`) and executes nothing; a concurrent different job is refused with `BUSY`. The job envelope is a closed schema: exact keys, a UUID `jobId`, a uint `epoch`, safe-integer timestamps, and a path-safe `tabRef`. Its size (64 KiB), `text` (4096), selector (512), and url (2048) are capped in UTF-8 bytes, not characters. A read is truncated to `maxBytes` (at most 16 KiB) at a code-point boundary; a job's reads share a 64 KiB budget, and an over-budget read fails with `READ_BUDGET`. `wait` supports only `state: attached` and `read` only `what: text`; other variants are refused with `INVALID_COMMAND`. Every CDP call, preflight included, is bound to the op's absolute deadline (the minimum of its own timeout and the job deadline), no call is sent after expiry, and an expiry bound by the job deadline ends the job `EXPIRED` by the bound that fired. A timeout after a mutation was dispatched reports `OUTCOME_UNKNOWN` (W.admission 9). `[unsure]` W.admission 9 proves that classification, not the no-call-after-expiry guard: the tab closes at the deadline, so a late `mouseReleased` has no page to reach; only W.admission 6 exercises the guard. Still deferred to Phase 1: the epoch floor (`OBSOLETE_EPOCH`), ledger retention and `EPOCH_FULL`, destination and stale-document checks, the network guard, and cancellation.
- **Not covered (Phase 1 after a GO, PW-plan dispositions).** No `HELLO` handshake in the lab: the pin is enforced on each job's signature, so an unpinned page can still link and ask `JOB_STATUS`. No destination check or network guard (finding 2): an allowlisted page whose form posts elsewhere is not exercised. The app variant, macOS, and the real recnrun.com origin.

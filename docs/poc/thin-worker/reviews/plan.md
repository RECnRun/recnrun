# Codex review of the plan (2026-11-06)

Codex (`gpt-6.1-sol`, high, read-only) reviewed the first draft of [PLAN.md](../PLAN.md) and [CHECKLIST.md](../CHECKLIST.md). The line numbers refer to that draft. Each finding was checked against the repository and Chromium's source, and its disposition follows the review.

## Review

1. **High — [PLAN.md:102](../PLAN.md): Origin checks cannot satisfy P1.14.** Checking the current main-frame URL before `click` allows an allowed page’s form to POST to a forbidden origin. Detecting the destination afterward cannot preserve the unchanged POST count required at line 131. **Fix:** specify checks of effective form/link destinations before activation, document-change race handling, and corresponding negative tests.

2. **High — [PLAN.md:104](../PLAN.md): Ledger pruning can permit repeated mutations.** A capped ledger can evict a completed request from the current epoch; replay then looks like a new request. The no-repeat claim has no retention or expiration rule. **Fix:** define durable rejection of requests outside the retained replay window, and test replay after eviction and restart.

3. **High — [PLAN.md:118](../PLAN.md): New workspaces are missing from gate integration tasks.** Current commands explicitly enumerate Vitest projects, dependency-cruiser app roots, and jscpd directories. They omit the proposed workspaces. Knip also explicitly configures the extension’s WXT entrypoints. **Fix:** add these configuration updates to P1.1/P1.2, with negative controls proving that every new workspace is tested and analyzed at unchanged thresholds.

4. **High — [PLAN.md:121](../PLAN.md): The two new safety checks would not run under their acceptance command.** `test:scripts:local` names two existing root checks and `scripts/poc-cross-profile/*.checks.mjs`; it does not discover `scripts/worker-cdp.checks.mjs` or P6.7’s `scripts/installer-lint.checks.mjs`. **Fix:** explicitly wire both into the gated command and prove its planted violations fail that command.

5. **High — [PLAN.md:142](../PLAN.md): The authorized FSA fallback has no green execution path.** A failed deciding cell remains an asserting failure, while the exact master manifest forbids `downloads` and the pass criteria require zero master downloads. Recording “fallback” does not resolve those contradictions. **Fix:** define the fallback implementation, permissions, read adapter, acceptance branch, and gesture accounting before Gate P1.

6. **Medium — [PLAN.md:140](../PLAN.md): The deciding-cell observer requires a forbidden permission.** The master cannot call `chrome.downloads.search` without `downloads`. Also, M-TW.1 observes the dashboard’s peer count despite requiring no extension tab open, and omits explicit offscreen recreation and provisioning/control round trips. **Fix:** use an independent downloads observer and file-based round-trip evidence while asserting no extension tab exists; repeat the complete cell manually. This matters because Chromium separately handles active and persisted grants in `PermissionGrantImpl::GetStatus` and `CleanupPermissions`. [Chromium source](https://raw.githubusercontent.com/chromium/chromium/main/chrome/browser/file_system_access/chrome_file_system_access_permission_context.cc)

7. **Medium — [PLAN.md:30](../PLAN.md): The suggested persisted-download mechanism is blocked.** Chromium’s `IsSettingReadOnly` explicitly marks `download.default_directory` read-only for `settingsPrivate`; `DownloadsHandler::FileSelected` persists it after a native folder chooser. **Fix:** eliminate `settingsPrivate.setPref` as the proposed route, identify a viable Chrome-owned mechanism early, and count any native-picker gestures. [Preference restriction](https://raw.githubusercontent.com/chromium/chromium/156.0.8078.80/chrome/browser/extensions/api/settings_private/prefs_util.cc), [settings handler](https://raw.githubusercontent.com/chromium/chromium/main/chrome/browser/ui/webui/settings/downloads_handler.cc)

8. **Medium — [PLAN.md:97](../PLAN.md): The fixed CDP table omits required methods.** Origin/document validation requires `Page.getFrameTree`, but it is absent from the table that P1.4 must enforce. The proposed CSP fallback also introduces unlisted methods. **Fix:** specify the complete allowlist, including shared validation methods and the selected `read` implementation, before implementing the static gate.

9. **Medium — [PLAN.md:82](../PLAN.md): P0.6’s red command selects no existing test.** `onboarding.spec.ts` has one title, “Prepare workers writes the request and follows the launcher's steps to the clones' acks”; it does not match `-g "error"`. A no-tests failure would not validate the hidden defect. **Fix:** first introduce a named asserting regression test and run that same test against the unfixed page and the fix.

10. **Medium — [PLAN.md:81](../PLAN.md): P0.5’s grep demands unrelated diagnostic deletion.** `debuggerDeclared` is also a report field in `src/diagnostics/report.ts` and several diagnostic tests, independently of `debuggerDeclared()` in `config/origins.ts`. **Fix:** target the obsolete helper/imports and build variants precisely; retain the diagnostic contract.

11. **Medium — [PLAN.md:154](../PLAN.md): The security replacement list is incomplete.** `forged-sender.spec.ts` separately checks forged presence/catalog, forged answers, forged offers, unchanged authorization/pins, and legitimate-peer recovery. The proposed replacement cases do not explicitly preserve all these supported contracts. **Fix:** enumerate each existing assertion and its replacement test before permitting deletion, as the phase’s own retention rule requires.

12. **Medium — [PLAN.md:156](../PLAN.md): Slow exploratory E13 cases remain without a disposition.** Replacing only frozen-clone cases leaves the non-frozen worker matrix and attached bootstrap diagnostic in `tests/headless/E13-separate-roots.spec.ts`; these still record verdicts rather than assert success. **Fix:** classify every E13 case: retain supported assertions, consolidate duplicated slice coverage, and move remaining diagnostics to the lab.

13. **High — [PLAN.md:201](../PLAN.md): Repair conflicts with immutable live bundles.** P6.6 requires repairing a deleted file, while P3.1 refuses writes into an existing version directory. Replacing that directory could also change files beneath running clones. **Fix:** define repair through a fresh immutable installation generation and stopped-clone migration, or refuse repair until references are stopped; test repair with a running clone.

14. **High — [PLAN.md:52](../PLAN.md): Installer ownership and deletion boundaries are unspecified.** `~/RECnRun` also contains browser data. “Removes exactly what it installed” and “leaves no file it wrote” do not distinguish application files, generated profiles, and pre-existing owner files. **Fix:** define ownership markers and data-retention behavior; require safe handling of existing files, symlinked paths, archive traversal/links, concurrent installs, and interrupted publication/uninstall.

15. **Medium — [PLAN.md:205](../PLAN.md): Trust review covers only the downloader.** The checksum establishes package integrity, but the neutral review receives only `install.sh`; package scripts can perform additional actions. P6.7’s explicit negative cases also omit telemetry. **Fix:** preserve the mandated blind review, add a separate audit of the pinned executable payload, and enforce forbidden actions across shipped scripts, including telemetry.

16. **Medium — [PLAN.md:197](../PLAN.md): The install friction boundary skips Store installation.** P6.9 starts from an empty home but assumes an installed master when onboarding opens. The Store install/confirmation and missing-master recovery are neither scripted nor explicitly counted. `install.sh --uninstall` also lacks a usable installed path or piped invocation. **Fix:** specify the complete starting state, count Store gestures separately and in the total, and document/test an exact one-command uninstall.

17. **Medium — [PLAN.md:199](../PLAN.md): Linux reboot recovery has no required evidence environment.** Unit-file checks do not exercise login startup, Docker boot is unresolved, and M-TW.5 covers macOS only. **Fix:** require a Linux VM/session acceptance check before claiming Linux recovery support, or explicitly defer that support.

18. **Medium — [PLAN.md:220](../PLAN.md): The soak’s equality is invalid under its crash model.** Most completed operations cause no POST, and a click can POST before crashing without recording `done`. Thus POST count cannot equal generic `done` results. **Fix:** correlate fixture effects with request IDs, count completed click mutations separately, and account for `OUTCOME_UNKNOWN` without permitting duplicate effects.

19. **Medium — [CHECKLIST.md:16](../CHECKLIST.md): The resume protocol contradicts Phase 0’s binding process.** “Run verify … only at gates” conflicts with PLAN line 73 and checklist line 35, which require timed green verify after every pruning step. **Fix:** explicitly exempt Phase 0 from gate-only verification while retaining gate-only pushes.

Read-only inspection covered the binding brief, diffs, named tests/configuration, and relevant Chromium source; the working-tree status remained unchanged. **Could not check:** runtime behavior, actual red/green failures, gate timing, installer safety in execution, or browser/manual acceptance. No files were edited, and no builds, tests, models, or browsers were launched.

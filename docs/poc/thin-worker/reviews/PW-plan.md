# Codex review of the Phase W plan (2026-11-06)

Model `gpt-6.1-sol`, high effort, read-only, on the saved diff before the fast-track block (`58ebfa67`). Verbatim answer, then the orchestrator's dispositions under the owner's fast track (GO/NO-GO first, coverage later).

1. **High — `docs/poc/thin-worker/PLAN.md:107,116`: W depends on provisioning changes deferred until P1.** W.rtc needs the Downloads adapter and trusted master pin, but the adapter is deferred and provisioning is declared unchanged. Existing `clone-open.sh:78` requires an extension master’s Downloads presence and extracts its key from that file; a website master supplies neither. **Fix:** bring the minimum adapter, marker-bound onboarding record, and record-only pin lookup into W before W.rtc, with script and browser acceptance checks.

2. **High — `docs/poc/thin-worker/PLAN.md:109,203`: W.trust overstates the worker’s protection.** W explicitly omits destination checks and the network guard. Its negative test merely names a forbidden origin in the envelope; an allowed-origin page can submit or redirect elsewhere before the next document check. **Fix:** include the guard in W and test forbidden form actions, redirects, and document races. Enforce the job’s narrowed origins throughout execution, rather than only the provisioning allowlist.

3. **High — `docs/poc/thin-worker/PLAN.md:268`: folder outcomes have no specified authentication.** The reopened page may consume results before establishing an authenticated link, although writable rendezvous files are inside the inherited threat model. A forged terminal result could falsify reconciliation and justify ledger retirement. **Fix:** define worker-signed outcome envelopes bound to worker identity, master, epoch, job digest, and sequence; verify them against the pinned worker. Add forgery, substitution, and rollback controls.

4. **High — `docs/poc/thin-worker/PLAN.md:32,123`: Option B’s safety contract is insufficient.** Skipping leaf symlinks and `.crdownload` files does not address symlinked ancestors, path replacement between checking and renaming, concurrent movers, destination collisions, permissions, or cross-device fallback. “Inside `~/RECnRun`” does not guarantee one filesystem. **Fix:** specify trusted roots, closed path grammar, completion evidence, ownership/modes, safe publication and collision rules, concurrency control, and fail-closed `EXDEV` handling. Require adversarial script checks for each case.

5. **High — `docs/poc/thin-worker/PLAN.md:32,317`: the R4 conflict remains unresolved.** The plan accepts a `Preferences` rewrite as tested behavior, while downloads-launcher `PLAN.md:26` explicitly forbids it. Existing `clone.sh:122` performs that rewrite; `prepare_copy` also deletes `downloads/RECnRun`, which the new byte-identity exception omits. **Fix:** record an explicit owner-approved R4 exception or choose a compliant mechanism, then reconcile the constraints and byte-comparison acceptance criteria.

6. **Medium — `docs/poc/thin-worker/PLAN.md:263`: the ten-minute cap can be bypassed with future timestamps.** Bounding `deadlineAt - issuedAt` does not bound execution from acceptance when `issuedAt` is arbitrarily far ahead. **Fix:** require safe integer timestamps, a positive interval, bounded future skew, and an acceptance-relative maximum runtime. Add future-issued, expired, malformed, and boundary cases.

7. **Medium — `docs/poc/thin-worker/PLAN.md:269,270`: the protocol remains underspecified outside the job envelope.** Cancellation lacks an explicit signed-byte definition and epoch/worker scope; status replies and terminal job states lack closed schemas. A crash after journaling but before sending also requires a defined response for an unknown job. **Fix:** specify canonical signing, domain separation, bounded request/reply schemas, terminal transitions, cancellation idempotency, and a non-replaying `NOT_FOUND` reconciliation path.

8. **Medium — `docs/poc/thin-worker/PLAN.md:292`: epoch retirement lacks a crash-safe transition.** The master’s stated precondition does not specify worker validation, acknowledgement, or persistence ordering between advancing the epoch floor and deleting entries. Incorrect ordering can make an old job appear new after restart. **Fix:** define the rollover exchange, persist the rejection floor before pruning, and test crashes at each persistence boundary plus replay after retirement.

9. **Medium — `docs/poc/thin-worker/PLAN.md:268,271`: ledger persistence does not guarantee folder delivery.** A worker can die after recording a terminal outcome but before publishing its download. Restart handling covers interrupted jobs, without requiring republication of completed outcomes. **Fix:** define a durable publication queue or deterministic regeneration from the ledger, with restart tests before download creation and before launcher movement.

10. **Medium — `docs/poc/thin-worker/PLAN.md:170–175`: lifecycle checks do not prove disconnected mutation execution.** Both planned closures occur after `click`; a worker that refuses all mutations after disconnect could still pass. **Fix:** close before a remaining mutation, prove its POST occurs while the master is absent, then reconcile. Validate the test with a worker deliberately stopping on disconnect.

11. **Medium — `docs/poc/thin-worker/PLAN.md:118,176`: the uncertainty test has no reliable crash boundary.** Holding a POST response does not hold `Input.dispatchMouseEvent` in flight: Chromium’s `InputInjector::OnInputEventAck` completes the CDP callback on input acknowledgement. A fixed two-second pause also makes cancellation timing fragile. **Fix:** use acknowledged lab barriers around durable `applying`, observed effect, and outcome persistence; kill or cancel at those barriers. ([Chromium input handler](https://raw.githubusercontent.com/chromium/chromium/main/content/browser/devtools/protocol/input_handler.cc))

12. **Medium — `docs/poc/thin-worker/PLAN.md:173,186`: the reconnect clock contradicts the sleep variant.** “Within 60 s of each close” cannot accommodate a 90-second freeze and differs from the owner’s requirement to reconnect within 60 seconds after reopening. **Fix:** start the reconnect timer at reopening or resume, and separately assert deadline behavior during the interruption.

13. **Medium — `docs/poc/thin-worker/PLAN.md:210`: the Store comparator depends on future work.** W.friction measures first result through P6.2, but Phase W builds no master extension and precedes P6. Counting two Store clicks alone cannot establish the complete comparator. **Fix:** identify an executable baseline available during W, or a recorded equivalent baseline with explicit assumptions. Count installation gestures even where CDP bypasses them.

14. **Medium — `docs/poc/thin-worker/PLAN.md:148–151,212`: additional thresholds change the owner’s decision criteria.** The brief requires recording network prompts and friction; the plan additionally requires a two-second link, zero baseline prompts, at most one public-origin prompt, and fewer gestures for both website paths. These can reject feasibility for criteria the owner did not bind. **Fix:** distinguish technical pass conditions from recorded performance/friction observations, and leave additional thresholds for the owner’s gate decision.

15. **Medium — `docs/poc/thin-worker/PLAN.md:100`: the public-origin emulation can produce misleading evidence.** The switch exists in Chromium 157, but merely recording its presence does not prove the intended address-space classification. Broad overrides could also reclassify worker endpoints. **Fix:** specify an endpoint-scoped value such as `127.0.0.1:<port>=public`, record effective classification and feature state, and add a permission-denial control. Pin the source revision before W; applicability to the installed Chrome remains untested. ([Override parser](https://raw.githubusercontent.com/chromium/chromium/157.0.8103.38/services/network/public/cpp/ip_address_space_util.cc))

16. **Medium — `docs/poc/thin-worker/PLAN.md:158`: install source does not prove the PWA permission path.** `PWAHandler::Install` exists, but `OriginHasExtendedPermission` checks a matching app’s scope and `INSTALLED_WITH_OS_INTEGRATION` state. **Fix:** specify manifest identity/scope and launch behavior, then record actual install state and persistent permission behavior. Linux Docker equivalence to native installation remains unsure until exercised. ([PWA handler](https://raw.githubusercontent.com/chromium/chromium/main/chrome/browser/devtools/protocol/pwa_handler.cc), [FSA permission context](https://raw.githubusercontent.com/chromium/chromium/main/chrome/browser/file_system_access/chrome_file_system_access_permission_context.cc))

17. **Medium — `docs/poc/thin-worker/PLAN.md:122,124`: Docker workspace and CA preparation are missing from task acceptance.** A separate lab app is feasible, but `Dockerfile.tests:30` copies only existing workspace manifests before installation. The CA setup also needs explicit tooling and the launching user’s NSS database. **Fix:** include Docker manifest/lockfile wiring and CA provisioning in W tasks; assert secure context, trusted chain, and rejection without the CA. Chromium documents NSS trust and its M146 database-location change. ([Chromium certificate setup](https://chromium.googlesource.com/chromium/src/+/main/docs/linux/cert_management.md))

18. **Medium — `docs/poc/thin-worker/PLAN.md:125–132,413`; `CHECKLIST.md:163`: acceptance and manual gates are incomplete.** Several W acceptance entries are filenames rather than runnable commands or negative controls. P7 still requires only M-TW.1–11, leaving new macOS and sleep evidence outside completion despite RESULTS depending on it. **Fix:** give each cell an exact command, artifact assertions, and expected red control; record downstream cells as not run after a deciding failure. Update manual gates and conditional RESULTS references, keeping M-TW.12 explicitly blocked until authorized.

Exercised: static comparison of the saved patch, brief, referenced repository files, and Chromium sources; no files changed, builds/tests run, or browsers launched, as requested.

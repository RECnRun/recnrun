## Review (verbatim)

1. **Blocker — concurrent submissions can execute the same mutation twice.** [runner.js:75](../../../../tests/lab/web-master/worker-extension/runner.js). Ledger lookup, `running` check, digest calculation, and persistence are separated by awaits; `running` is assigned afterward. My in-memory probe submitted the same signed job concurrently: both returned `ACCEPTED`, two runners started, and only one ledger entry remained. The serial lifecycle tests cannot detect this, so RESULTS’ “one job at a time” and ledger protection claims are unsupported. **Change:** serialize admission through durable acceptance; test concurrent identical jobs and concurrent different jobs, asserting one execution.

2. **Major — the advertised byte caps are not enforced.** [job-check.js:74](../../../../tests/lab/web-master/worker-extension/job-check.js), [ops.js:85](../../../../tests/lab/web-master/worker-extension/ops.js). Envelope size and read truncation count JavaScript string units. A correctly signed **84,733-byte** envelope passed validation; a read capped at 16,384 returned **49,152 UTF-8 bytes** in my probes. There is also no cumulative read budget: 32 maximum ASCII reads permit 512 KiB. W.trust’s ASCII oversized-envelope and oversized-argument cases miss these failures. **Change:** enforce UTF-8 byte limits and a cumulative 64 KiB result budget, with Unicode and aggregate-read negative cases; correct [RESULTS.md:99](../../../../docs/poc/thin-worker/RESULTS.md).

3. **Major — the deadline does not cover preflight, and timeout does not stop the operation.** [ops.js:107](../../../../tests/lab/web-master/worker-extension/ops.js), [runner.js:27](../../../../tests/lab/web-master/worker-extension/runner.js). `checkOrigin` runs before the timeout race. With a delayed mocked origin check, the actual runner sent all three click events **55 ms after the job deadline** and persisted `DONE`. Separately, releasing a blocked mouse command after `execute` returned `FAILED/TIMEOUT` allowed the remaining mouse commands to continue. The never-matching `wait` test supports that particular timeout path, not the general deadline claim. **Change:** carry an absolute deadline through checks and CDP sequences, prevent subsequent input after expiry, and settle or terminate outstanding work before declaring completion. Preserve `OUTCOME_UNKNOWN` where dispatched mutation effects remain uncertain.

4. **Major — the envelope is only partially strict, and epoch protection is absent.** [job-check.js:72](../../../../tests/lab/web-master/worker-extension/job-check.js), [ledger.js:5](../../../../tests/lab/web-master/worker-extension/ledger.js). A signed job with string timestamps, object-valued `epoch`, null `tabRef`, and `jobId: "../outside"` passed my probe. Arithmetic coercion validates timestamp differences without validating timestamps themselves; string deadlines also change the meaning of `deadlineAt + 5000`. The ledger uses only `jobId`, with no epoch floor or retention cap. **Change:** implement the complete closed schema, safe integer timestamps, UUID/path-safe identifiers, scoped ledger keys, and crash-safe epoch rejection before promoting this code. Epoch/retention work was explicitly deferred; W4 must not imply it already protects the lab.

5. **Major — RESULTS overstates origin confinement.** [ops.js:91](../../../../tests/lab/web-master/worker-extension/ops.js), [RESULTS.md:99](../../../../docs/poc/thin-worker/RESULTS.md). The tests establish refusal of forbidden origins named in envelopes and navigation arguments. They do not establish confinement of effects or reads: there is no destination inspection, document-race check, or request guard. The following “Not covered” paragraph acknowledges this, but the preceding assertion that changed code remains within allowlisted origins is broader. **Change:** describe the measured envelope checks precisely; carry destination, redirect, stale-document, and network-guard cases into Phase 1. This deferral is authorized by PW-plan and need not independently block the fast track.

6. **Major — W.fsa can pass after spending a gesture on the first restart.** [w-fsa.spec.ts:122](../../../../tests/lab/web-master/w-fsa.spec.ts). `restart-1` permits restoration when none occurred earlier, and the final assertions inspect permission **after** that restoration. A run violating the fast-track “no gesture after onboarding” criterion could therefore pass. The archived JSON supports the reported strict success: restoration occurred at `onboarding-reopen`, with both restarts already granted. **Change:** disable restoration after the declared onboarding boundary and assert no subsequent prompts/gestures. The marker, write-back, permission, and identity assertions otherwise directly test W2.

7. **Major — W5 establishes a comparison against an assumed Store flow.** [friction-harness.ts:42](../../../../tests/lab/web-master/friction-harness.ts), [w-friction.spec.ts:149](../../../../tests/lab/web-master/w-friction.spec.ts). Store’s eight gestures are a constant, including two unproved restore gestures. A genuinely cheaper Store installation would not fail this spec; changing the constant only validates the arithmetic. The automatic pinning handoff is also replaced by `lab.provision` after pairing, so its real interaction cost remains **[unsure]**. **Change:** label W5 a conditional estimate pending an executable Store comparator and real provisioning handoff. Preserve its explicitly non-deciding status.

8. **Minor — W.rtc asserts connectivity, but records several other conditions without asserting them.** [w-rtc.spec.ts:196](../../../../tests/lab/web-master/w-rtc.spec.ts). mDNS candidates, successful pairs, worker proof verification, and completing 100 ordered pings meaningfully test the core hypothesis. However, public address classification and LNA state are only logged; a failed public-origin override would still pass. The archived JSON does show `Public`, so this does not invalidate that observation. Corrupting the DTLS fingerprint tests transport failure rather than rejection of a wrong pinned identity. **Change:** assert classification and add a wrong-key control with otherwise valid SDP; keep prompt and latency observations distinguished from assertions.

9. **Major — Phase 1 must preserve the worker’s focus-emulation fix and prove operation without harness flags.** [runner.js:51](../../../../tests/lab/web-master/worker-extension/runner.js), [lifecycle-harness.ts:135](../../../../tests/lab/web-master/lifecycle-harness.ts). Moving focus emulation into the worker makes the revised W3 pass meaningful; it is no longer supplied by Playwright’s attachment to the job page. Chromium’s `EmulationHandler::SetFocusEmulationEnabled` explicitly raises the capturer count with `stay_hidden=false`. **Change:** add this dependency to the fixed CDP table/static check or exercise an alternative; the current protocol table omits it. Repeat headed/headless execution without remote-debugging, unsafe-extension-debugging, or silent-debugger flags. Their necessity remains **[unsure]**. Brief service-worker inspection also remains; it should not be represented as entirely unobserved execution. Chromium’s `ExtensionDevToolsClientHost::Attach` provides the worker’s own debugger keepalive, so harness attachment alone is not grounds to reject W3. ([Emulation source](https://raw.githubusercontent.com/chromium/chromium/157.0.8103.38/content/browser/devtools/protocol/emulation_handler.cc), [debugger source](https://raw.githubusercontent.com/chromium/chromium/157.0.8103.38/chrome/browser/extensions/api/debugger/debugger_api.cc))

10. **Major — the tests do not establish durable pairing or authenticated reconciliation.** [offscreen.js:1](../../../../tests/lab/web-master/worker-extension/offscreen.js), [lifecycle-harness.ts:168](../../../../tests/lab/web-master/lifecycle-harness.ts). Worker identity is regenerated with the offscreen document, and each connection receives a fresh trusted key directly from the harness. `JOB_STATUS` requires no master authentication. W4 does meaningfully demonstrate rejection of new-key jobs after site-data clearing, but that is mutation refusal, not authenticated-link or result-confidentiality protection. **Change:** carry persistent identities, onboarding-bound pins, mutual HELLO authentication, and authenticated status/results into Phase 1, as the dispositions require.

11. **Major — terminal ledger persistence can permanently lose folder delivery.** [runner.js:61](../../../../tests/lab/web-master/worker-extension/runner.js), [ledger.js:43](../../../../tests/lab/web-master/worker-extension/ledger.js). Terminal state is saved before publication, but recovery republishes only nonterminal jobs. A crash after the terminal save, or during its download, leaves no recovery path for the missing file. W3 kills before the click outcome is recorded, so it misses this boundary. **Change:** carry a durable publication queue or deterministic regeneration, signed outcome envelopes, and crash tests around publication into Phase 1. Also correct RESULTS’ suggestion that folder signalling belongs to W.fsa: W.fsa exercises folder access, not worker signalling or launcher movement.

12. **Minor — accepted operation options exceed implemented semantics.** [ops.js:47](../../../../tests/lab/web-master/worker-extension/ops.js), [ops.js:75](../../../../tests/lab/web-master/worker-extension/ops.js). `wait` ignores `state`, and `read` ignores `what`; visible/text waits and value reads silently behave as attached waits and text reads. W3 uses only the implemented variants. **Change:** reject unsupported variants in the lab or implement them; test every accepted variant in Phase 1.

13. **Major — GO must carry an explicit unfinished-work contract.** [PW-plan.md:54](../../../../docs/poc/thin-worker/reviews/PW-plan.md), [CHECKLIST.md:53](../../../../docs/poc/thin-worker/CHECKLIST.md). Beyond the fixes above, retain real folder signalling/provisioning, safe launcher movement and R4 reconciliation, signed cancellation and bounded status schemas, epoch retirement, resubmission/replay tests, strict-CSP execution, app closure, suspend/resume, and macOS/real-origin validation. W3’s POST-after-disconnect and crash-barrier assertions support the narrow lifecycle result; they do not complete these deferred cases. **Change:** name their Phase 1 acceptance tests, preserve the website-origin trust risk for the owner’s decision, and complete the recorded Gate W verification and approval requirements.

Exercised: read-only diff/source review, archived JSON inspection, Chromium source checks, and in-memory Node probes reproducing admission, cap, schema, and deadline defects. `git diff --check` passed; the working tree remained clean. No files changed or browsers launched; browser tests and `verify` were not rerun.

# E13: headless workers on separate roots, driven by the master with peer commands

Task P7.4 of [PLAN.md](../PLAN.md) (T6 to T9), build variant `poc-d0` installed unpacked over the DevTools pipe (`diagnostic`; external client true for the master and for the install, none on any worker afterwards), namespace `lab`. Lab: Google Chrome 157.0.8103.38 on Linux in Docker on Xvfb, three samples per cell (`E13.diag.bootstrapTab` one), run `2026-11-05T23-43-44.405Z-29471de0-f643-4845-b7ad-f12dd8ecc5f9` (after the P7 review fixes and the SIGINT quit). Host: Google Chrome 156.0.8078.80 on macOS 27.0.1 (arm64), on throwaway roots under `~/Documents/RECnRun/poc-downloads-launcher/roots/` with a throwaway headed master, three samples per cell, run `host-2026-11-06T00-00-43.212Z`; the personal Default was not touched, and its cells wait for the owner ([M-P7.a](../MANUAL_VALIDATION.md#after-p7)). Verdict files: [lab](verdicts/E13-lab.json), [lab versions](verdicts/E13-lab-versions.json), [host](verdicts/E13-host.json), [host versions](verdicts/E13-host-versions.json). Chrome's rule that headless takes one target is in `chrome/app/chrome_main.cc` (`ChromeMain`), read before measuring; a worker's only tab is `bootstrap.html`, which `tabs/open-tabs.ts` (`toBrowserTabs`) never shares.

## Question

With the master on a root of its own and each worker on a root of its own, opened by `open.sh` / `clone-open.sh` in `--headless=new` with no debugging flag and no CDP client, can the master link to every worker, command it, read its tabs, navigate it, and tell it apart by a marker, and does the same root keep its identity when alternated between visible and headless?

## Method

- Master: a headed Playwright Chrome on Xvfb on its own root; it stands in for the personal Default, which the lab never has. It is the observer: everything it learns of a worker arrives over the verified link.
- Workers (V1): `poc-d0` installed by CDP into one root each, then opened by `open.sh open ... headless`. Their binding to the master is written by the harness while the installer is attached (`e13-lab.ts` `bindWorker`: the master's pin in `local:peerPins` and `local:role`), and the master's side by `bindMaster` once they link; in the product the local channel writes both. Clones (V2): created and opened by `clone-open.sh`, provisioned as in P5.5; the harness writes the master's `boundWorkers`.
- Page: a static loopback server (`e13-site.ts`) serves `/start/<marker>` (redirects after 2 s) and `/marker/<marker>` (title `marker:<marker>`, sets cookie `e13`) and logs every request.
- Driving a headless worker: the new peer command `OPEN_TAB` (page request `open-tab`), from the master only, http(s) only, opens a tab in the worker's first normal window ([ARCHITECTURE.md](../../../ARCHITECTURE.md), Messages and Executor). The ack and the echoed url prove nothing. A cell passes only on what the worker reports of its own fresh tab (a tab titled `marker:<marker>` in the `tabs` snapshot) and on the server's log (`/start/<marker>` then `/marker/<marker>`).
- Mode checks: `--headless` exactly when asked, no `remote-debugging` flag, no `DevToolsActivePort`, and no X window owned by a headless worker's processes.

## Observation

- t6.workers: four workers per sample opened in 1.1 s each, presence after 0.3–0.5 s, ack after 0.2–0.3 s, four distinct pids, all four linked in every sample.
- t6.commands: every worker opened the page and reported `marker:<own marker>`; `activate` answered ok for each.
- ops.navigation: for each worker the server saw `/start/<marker>` then `/marker/<marker>`, and the worker's tab url was the marker url.
- t7.background: with one blank page on the master, all four links stayed; after stopping one worker the link dropped in 2.6–2.9 s, and a new open relinked within 0.1 s of its ack.
- t8.alternate: the same fingerprint (`72:1E:90:15`) in all nine passes, linked each time; the cookie was empty on the very first start and `e13=<marker>` on every headed start after it.
- t9.*: three clones per sample, each sample on a fresh clones directory, open in 1.0–1.1 s with the ack after 0.1–0.2 s; three distinct identities; tabs, marker and commands as for V1; asking a headless clone for headed (and the reverse) exits 65 in all three samples with one main process, same pid, and no window appeared; each sample quits the headed-side clone by SIGINT and reopens it headed first, and all three reopens succeeded.
- diag.bootstrapTab: with Playwright attached to a headless worker, its targets are the service worker, the offscreen document, and one page, `bootstrap.html#token=diagnostic`; the product shares 0 tabs of it.
- focus, pip: unavailable, headless has no window or picture-in-picture surface.
- Host: four workers per sample opened in 2.2–2.5 s each, presence after 1.3–1.8 s, ack after 1.5–2.0 s, all four linked in every sample; commands, navigation, and markers as in the lab; with no master page the links stayed, a stopped worker dropped in 2.1–2.6 s and relinked 0.6–1.6 s after its ack; the alternated root kept fingerprint `88:DE:8E:F2` and its cookie across nine passes. The clone cells and the diagnostic are `unavailable` on the host, with the reason in the verdict: they need the owner's personal Default as master, which this run never launches (M-P7.a).

- The receive-side refusal (a relay, a template, a worker, an unbound master, a non-http(s) url) is covered by unit tests, with no `tabs.create` call, in `apps/extension/tests/open-tab-authorization.test.ts`, red and green in the commit with subject "Add a peer command that opens a web page in a worker's tab".

## Limits of this measurement

- Three samples per cell: a rate, not a bound on rare failures.
- The binding of V1 workers and the master's side of the clones are written by the harness; the product writes them through the local channel.
- Linux Chrome on Xvfb. The host twin (`tests/host/E13-separate-roots.spec.ts`) covers the worker cells with a throwaway headed master and throwaway worker roots; macOS has no X server, so a headless worker is judged by its command line alone. It records the clone cells and the diagnostic unavailable: they need the lab's attached master or a debugging port on a worker, and the owner's personal Default is never launched.
- `OPEN_TAB` means a compromised bound master can make a worker load any http(s) url; there is still no arbitrary code, page content, or storage access.

## Conclusion

In the lab, a master on its own root linked to every headless worker and clone on separate roots, opened a page in each with `OPEN_TAB`, read each worker's own fresh tab and marker, navigated it, and activated it, while the same root kept its identity across visible and headless opens. Focus and picture-in-picture do not apply to headless. On the host, the same worker cells passed on macOS with a throwaway master; the clone cells with the personal Default as master wait for the owner (M-P7.a).

## Findings

1. **should fix — [clone-open.sh:104](../../../../scripts/poc-cross-profile/clone-open.sh#L104).** `read_clone_ack` checks independent substrings rather than a closed grammar. It accepts non-JSON text and `"identity":{}` without a key, signature, or timestamp, then registers the clone. Parser probes confirmed both cases. **Fix:** consume the complete writer layout with `ack_take`, validate every field, and require no trailing bytes.

2. **should fix — [clone.sh:76](../../../../scripts/poc-cross-profile/clone.sh#L76), [clone.sh:189](../../../../scripts/poc-cross-profile/clone.sh#L189).** The marker readers validate shell strings without first validating raw bytes. Dash discards embedded NULs: a marker containing `role=wor<NUL>ker` passes. `list-clones` also calls `read_clone_marker` without the 2 KiB limit enforced by `open-clone`. **Fix:** put the size and printable-ASCII/LF checks inside shared marker readers, before either read loop.

3. **should fix — [base-freeze.sh:64](../../../../scripts/poc-cross-profile/base-freeze.sh#L64).** Freeze writes `unpackedPath` without checking the grammar that `read_base_marker` requires. For example, `settings_path` supports a build directory containing spaces, but the resulting frozen marker is rejected by `clone.sh`. **Fix:** use one unpacked-path grammar for writing and reading; reject unsupported paths before freeze reports success.

4. **should fix — [prepare.ts:16](../../../../apps/extension/src/p2p/prepare.ts#L16).** `BasesDirSchema` and `parse_request` accept paths that the base commands reject, including `/Users/me/My Bases`. They also accept trailing or empty segments that the registry’s root grammar rejects. The dashboard therefore accepts requests that cannot complete. **Fix:** align the choice schema and request parser with the launcher’s canonical path grammar.

5. **should fix — [provision.sh:90](../../../../scripts/poc-cross-profile/provision.sh#L90).** `is_count` accepts leading zeros, so the claimed closed JSON parser accepts `"clones":01`, which is invalid JSON and cannot be produced by the extension. This passed parser probes on both shells. **Fix:** validate this field as exactly one character from `1` through `8`.

6. **should fix — [prepare.ts:78](../../../../apps/extension/src/p2p/prepare.ts#L78).** Status validation permits duplicate clone names and instance IDs. Listing the same acknowledged worker twice satisfies the reducer’s count for a two-worker operation and shows Done with only one worker present; an in-memory check reproduced this. **Fix:** require unique names and instance IDs, and require the expected `w1`…`wN` rows before completion.

7. **should fix — [prepare.ts:84](../../../../apps/extension/src/p2p/prepare.ts#L84).** `readStatus` has no size limit before `JSON.parse`, unlike the request and other rendezvous readers. A valid status padded to over 200 KB was accepted. **Fix:** enforce a shared maximum status size before parsing, with an oversized-file negative test.

8. **should fix — [bootstrap.ts:43](../../../../apps/extension/src/diagnostics/bootstrap.ts#L43).** Clone fragments require a letter-leading namespace of at most 32 characters, while the shell and `NamespaceSchema` accept `[a-z0-9-]{1,40}`. A supported namespace such as `1lab` therefore reaches Chrome but is refused by its bootstrap page. **Fix:** validate the extracted namespace with the shared schema.

9. **should fix — [clone-provisioning.ts:64](../../../../apps/extension/src/background/clone-provisioning.ts#L64).** The durable role changes to worker before boot adoption, certificate/identity statement creation, and ack writing. Failure or termination afterward leaves startup permitted to announce an incompletely provisioned worker. A failing-statement probe left the role as worker. **Fix:** keep outward work gated until provisioning and its correlated ack finish, using a pending state if necessary.

10. **should fix — [clone-provisioning.ts:102](../../../../apps/extension/src/background/clone-provisioning.ts#L102).** The listener accepts every page belonging to the extension, including `dashboard.html`; it does not require the launcher’s clone bootstrap URL or correlate the message with that URL. A listener probe confirmed dashboard-origin provisioning is accepted. **Fix:** require the bootstrap pathname and match the request against its validated token, instance, operation, namespace, and master binding before changing storage.

11. **should fix — [poc-template-repository.ts:17](../../../../apps/extension/src/storage/poc-template-repository.ts#L17).** Transient cleanup omits `local:pocPaused`. Unlike the transport error, the template’s stored pause survives provisioning and appears in the clone’s diagnostics until subsequently replaced. **Fix:** remove the pause value during initial template/clone cleanup and test with a seeded pause.

12. **should fix — [clone-open.sh:140](../../../../scripts/poc-cross-profile/clone-open.sh#L140).** Each clone opening generates a new `operationId`; `provision.sh` neither passes the onboarding operation ID nor checks the returned one. Consequently the workers’ acks are correlated to different operations from the dashboard request, contrary to P6.1. **Fix:** pass the parent operation ID into clone opening and verify that exact ID before recording completion.

13. **should fix — [downloads-transport.ts:136](../../../../apps/extension/src/p2p/downloads-transport.ts#L136).** If the reader is absent from the catalog and a listed peer’s root has no mapping, `baseOf` falls back to the reader’s own root. It then reads that peer’s files despite decision 11’s missing-path exclusion. A read-spy probe confirmed those reads. **Fix:** remove this fallback; use the local root only when shared-root membership is established.

14. **blocker — [base-update.sh:45](../../../../scripts/poc-cross-profile/base-update.sh#L45).** Base update lacks the clone copier’s stray-link checks. A copied `downloads` symlink makes cleanup delete `RECnRun` outside the copy; a copied `Default` symlink makes `up_rewrite` overwrite external Preferences. The final-file check does not detect an intermediate symlink. **Fix:** reject stray links in both source and copy before copying or mutating, using the clone copier’s existing checks.

15. **should fix — [provision.sh:185](../../../../scripts/poc-cross-profile/provision.sh#L185).** `.run.out` and `.run.err` are predictable, non-exclusive redirection targets. Pre-existing symlinks are followed and their targets truncated; checking the parent `ops` directory does not protect these files. **Fix:** create an exclusive private temporary directory and keep both output files inside it.

16. **blocker — [provision.sh:205](../../../../scripts/poc-cross-profile/provision.sh#L205).** `create-base` leaves Chrome running, but the following install step invokes `install.sh`, which refuses any root still held by a process. Fresh automatic onboarding therefore stops at install. The onboarding lab masks this by preinstalling the extension at [onboarding.spec.ts:59](../../../../tests/browser/onboarding.spec.ts#L59); E10 constructs an already-closed root directly. **Fix:** perform the verified base quit before installation, and exercise the real create→install handoff without preinstallation.

17. **nit — [CHROMIUM.md:303](../CHROMIUM.md#17-a-new-cookie-reaches-the-disk-after-about-30-seconds-and-sigterm-does-not-wait-for-it).** “The launcher never ends Chrome itself” contradicts `base.sh quit` sending SIGTERM and `install.sh` closing Chrome through CDP with a SIGTERM fallback. **Fix:** describe those termination paths explicitly and retain the cookie-flush limitation.

Overall, I would hold this range from pushing: the install handoff blocks fresh onboarding, and base update can mutate files outside its copy. The remaining findings weaken the promised file boundaries and provisioning guarantees. Exercised: in-memory parser/schema/provisioning/transport probes reproduced the acceptance and ordering defects above; syntax checks passed for all nine named shell files under both shells. Repository suites, browser runs, and `vp run verify` were not run in this read-only session; no files were changed.

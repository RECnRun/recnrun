## Run 1: P1.0–P1.3

1. **High — [scripts/test-container.mjs:125](../../../../scripts/test-container.mjs#L125).** An internal Docker network does not enforce the plan’s loopback-only rule: containers can still reach their peers and the bridge gateway’s host services. [Docker explicitly documents these exceptions](https://docs.docker.com/reference/cli/docker/network/create/#network-internal-mode---internal), while the guard tests only public destinations. Add filtering that blocks traffic leaving the container’s namespace, retain the interface needed for ICE, and test gateway and peer-container destinations.

2. **Medium — [tests/host/fixtures/downloads.ts:37](../../../../tests/host/fixtures/downloads.ts#L37).** The default-download workspace lacks the roots fixture’s exclusive creation and symlink checks; its only containment check compares the reported pathname’s parent after the write. Existing symlinks can redirect writes and cleanup outside the intended subtree, and exceptions before `cleanDefault()` leave Downloads artifacts behind. Prepare an exclusively owned, marked directory before downloading, reject symlinked ancestors, and clean owned artifacts in `finally`.

3. **Medium — [tests/host/fixtures/downloads.ts:77](../../../../tests/host/fixtures/downloads.ts#L77).** If `Browser.getVersion` or evidence recording fails after `launchProbe()` succeeds, the catch block removes the profile root without closing its Chrome process. An in-memory failure injection reproduced root removal with no Chrome close; retain the launched handle and close it before removing the root.

4. **Medium — [apps/extension/src/background/start.ts:12](../../../../apps/extension/src/background/start.ts#L12).** POC modes return true from `peersEnabled()`, but this separate predicate excludes them, as does the dashboard’s predicate. Consequently, the POC variants disable the background mesh and pairing UI despite P1.1 claiming they enable the mesh. Update both predicates and exercise the actual POC builds, while retaining the production exclusion checks.

5. **Medium — [tests/experiments/fixtures/downloads-verdicts.ts:38](../../../../tests/experiments/fixtures/downloads-verdicts.ts#L38).** Unexpected harness failures become measured samples with empty observations, allowing the completeness test to pass even when the experiment never ran; `outcome.ts` repeats this behavior for E1. Injecting “diagnostics page never started” produced three samples and satisfied the completeness condition, contrary to section 8. Propagate setup and harness errors, and record failed hypotheses only after their measurement actually executes.

6. **Medium — [tests/experiments/fixtures/downloads-cells-states.ts:114](../../../../tests/experiments/fixtures/downloads-cells-states.ts#L114).** The interrupted-download verdict checks only that four reads return the previous profile ID; a controlled run with no partial files and downloads already `complete` still passed. Moreover, committed dropped-connection samples require a fallback cancellation, so they do not prove automatic cleanup after interruption as the E2 table suggests. Require the intended download states, observed partial files, exact retained publication, and verified cleanup, and distinguish network interruption from explicit cancellation in the verdict and report.

7. **Medium — [apps/extension/src/p2p/downloads-rendezvous.ts:92](../../../../apps/extension/src/p2p/downloads-rendezvous.ts#L92).** An expired replacement immediately discards a still-valid cached publication, breaking P1.3’s requirement that the last valid publication stand until its TTL. The reader also accepts future creation timestamps and compares against an expired previous publication, which can reject a subsequent valid publication as `older`. Validate timestamp relationships, compare only against a usable cached value, and preserve that value when rejecting an expired replacement.

8. **Medium — [tests/experiments/fixtures/downloads-cells-states.ts:196](../../../../tests/experiments/fixtures/downloads-cells-states.ts#L196).** `E2.traces` passes solely because the probe request succeeds, even without a display or a working history query; both conditions passed an in-memory negative control. Thus the host verdict does not establish the listed visible traces, and E2.md’s statement that both environments agree on every prediction also overstates the unavailable host prompt measurement. Split observable checks from unavailable UI measurements and narrow the report accordingly.

9. **Low — [tests/experiments/fixtures/downloads-verdicts.ts:53](../../../../tests/experiments/fixtures/downloads-verdicts.ts#L53).** E2 omits top-level `gestures` and `steps`, including for the Save dialog, unlike E1’s common recorder. Its separate host append path also omits smoke stamping, so a host run with `RECNRUN_EXPERIMENT_SAMPLES=smoke` can produce reduced evidence without `mode: "smoke"`. Reuse the common recording path and preserve both gesture accounting and sample-mode metadata.

10. **Low — [apps/extension/src/entrypoints/diagnostics/main.ts:14](../../../../apps/extension/src/entrypoints/diagnostics/main.ts#L14).** The diagnostics entrypoint implements file reading, publication handling, messaging wrappers, and report construction despite the scoped rule requiring thin wiring. This places executable logic outside normal coverage and leaves runtime replies unchecked. Move it into a tested module, validate replies at the receiving boundary, and have the entrypoint call its starter.

The central conclusions are supported for the measured diagnostic CDP installs: E1 records exact file reads with the host permission and zero gestures, alongside permission and toggle controls; E2 records relative writes, absolute `DownloadItem.filename` values, and successful readback. They do not yet approve the personal Default’s manual install path, strict execution without CDP, or the broader interrupted-download and host-UI claims above. Exercised: 12 existing manifest/image checks passed, plus read-only in-memory reproductions of the reported logic gaps; browser experiments, fresh build byte comparisons, and full `verify` were not rerun because this session is read-only.

## Run 2: E3 (P1.4)

1. **Medium — [apps/extension/src/background/poc-file-read.ts:35](../../../../apps/extension/src/background/poc-file-read.ts#L35).** Concurrent reads can forward a request before the offscreen listener is ready: `ensureOffscreen()` returns when `getContexts()` finds a document, even while its `creating` promise remains pending. Chromium distinguishes frame existence from completed loading (`RuntimeGetContextsFunction::GetFrameContexts` in [runtime_api.cc](https://raw.githubusercontent.com/chromium/chromium/main/extensions/browser/api/runtime/runtime_api.cc), versus `OffscreenCreateDocumentFunction::OnExtensionHostDidStopFirstLoad` in [offscreen_api.cc](https://raw.githubusercontent.com/chromium/chromium/main/extensions/browser/api/offscreen/offscreen_api.cc)); an in-memory reproduction confirmed the early return. Await pending creation before accepting an existing context, coordinate closure with creation, and add deferred-start and close/recreate regression tests.

2. **Medium — [tests/experiments/e3-samples.ts:170](../../../../tests/experiments/e3-samples.ts#L170).** The cache verdict permits the first post-change read to return stale bytes and still passes when the following read succeeds; I reproduced this, so it does not enforce E3.md’s “next read” conclusion. The committed zero-poll observations establish immediate freshness for the sampled A→B transitions, but each sample stops before exercising sustained polling or further default-cache updates, and the permanent-staleness control misses this distinction. Repeat updates at the real polling interval, add a temporarily stale control, and either require freshness on the first read or narrow the report to the tested guarantee.

3. **Low — [docs/poc/downloads-launcher/experiments/E3.md:42](../experiments/E3.md).** The report explicitly acknowledges that caching and directory listings were not inventoried in Chromium, yet uses their observed behavior to recommend an adapter design. This violates AGENTS.md’s requirement to inspect the deciding Chromium code before building on a Chrome hypothesis. Inventory the applicable file-loader path, including `FileURLLoaderFactory::CreateLoaderAndStart`, `FileURLLoader::Start`, and `FileURLDirectoryLoader::Start`, then reconcile its predictions with E3’s measurements.

4. **Low — [tests/host/E3-file-read.spec.ts:18](../../../../tests/host/E3-file-read.spec.ts#L18).** The host hypothesis list omits `E3.directoryListing`, allowing “every E3 hypothesis left a verdict” to pass despite the report marking that cell “not run.” P1.4 lists this hypothesis, and plan section 8 requires an explicit outcome rather than silently omitting it. Add it to the host list and record `unavailable` with the prescribed parser reason; this requires no directory read or disclosure of host paths.

5. **Low — [.dependency-cruiser.cjs:212](../../../../.dependency-cruiser.cjs#L212).** The new restriction excludes `diagnostics` from content, dashboard, tabs, and ports, but `extension-views-shared` still permits views to import it despite the updated architecture text claiming otherwise. Introducing the folder also leaves it outside the existing restrictions on imports from `p2p` and `offscreen`. Extend those restrictions to enforce the documented boundaries and exercise them with controlled forbidden imports.

E3’s conclusion is supported for the recorded diagnostic runs: both contexts returned the exact bytes, and every sampled first read after modification saw the change. That supports the observed cases, with limited evidence for sustained cache behavior; host execution uses guarded throwaway roots, and the spelled-out production gate appears sound.

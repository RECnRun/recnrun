## Findings

1. **High — [lifecycle.sh:79](../../../../scripts/poc-cross-profile/lifecycle.sh#L79).** The signal guard can accept the wrong process. It searches rendered `ps` text for a substring rather than verifying executable and argument boundaries. A mocked `ps` probe showed that recorded root `/tmp/root` matches an actual argument `/tmp/root other`. State bindings are not checked against the record, and `--force` does not revalidate identity before SIGKILL. `launcher_pid()` similarly accepts another launcher's PID without checking its state directory. Validate registered bindings, executable, exact arguments, and process start identity before each signal.

2. **High — [lifecycle-state.sh:16](../../../../scripts/poc-cross-profile/lifecycle-state.sh#L16).** Shared-root protection counts registrations rather than Chrome profiles. Registering only Default in a root containing other profiles produces `shared=0`, permitting a signal that closes all its profiles. Main-PID adoption also runs only for `shared=1`; otherwise an already-running Chrome leaves the exited forwarder's PID in state. Chromium's `ProcessSingleton::NotifyOtherProcessWithTimeout` (`chrome/browser/process_singleton_posix.cc`, Chromium 156.0.8078.80) confirms that forwarding is per user-data directory. Resolve ownership for every root, refuse signals where exclusivity is unproved, and test an unregistered sibling plus Chrome opened normally by its owner.

3. **High — [lifecycle-state.sh:67](../../../../scripts/poc-cross-profile/lifecycle-state.sh#L67).** Dead-lock takeover can admit two holders. Two reclaimers can both finish the second read of the dead PID; one removes the stale lock and acquires it, then the other removes that new lock using its earlier observation. The comment acknowledges this window. Atomic hard-link acquisition does not make reclamation atomic. Serialize reclamation and add a controlled concurrent-takeover test proving that the winner's lock survives.

4. **High — [lifecycle.sh:196](../../../../scripts/poc-cross-profile/lifecycle.sh#L196).** Launch completion can overwrite a concurrent pause, stop, or replacement attempt. `launch()` releases the profile lock before opening Chrome; both `launched()` and the final state update write without reacquiring it or checking an attempt identifier. A delayed success changes `paused` or `stopped` back to `open`; a timeout can likewise replace a newer state. Persist the attempt token before spawning, lock every callback/completion, and accept results only for the still-current attempt. Exercise delayed completion, cancellation, and crashes around PID publication.

5. **High — [open.sh:94](../../../../scripts/poc-cross-profile/open.sh#L94).** Ack acceptance does not establish the identity or current boot required by decision 11. It checks a prefix and extracts the first `"boot"` anywhere. An in-memory probe accepted malformed JSON containing an arbitrary identity, a boot nested inside that identity, no timestamp, and trailing garbage. The browser helper checks neither identity equality nor its schema. Parse the complete closed grammar, validate the identity, and match identity and boot against the current registration. Add malformed, mismatched-identity, stale-boot, and trailing-byte controls.

6. **High — [first-run.sh:92](../../../../scripts/poc-cross-profile/first-run.sh#L92).** First run cannot provision the usual shared-Downloads layout. It skips every `shared` binding, although these profiles are precisely the ones requiring token-based binding. For `distinct` bindings, `presences_at()` identifies profiles from filenames without reading or validating their contents. The script never bootstraps candidates to establish their identities, and it performs no retry for the approximately ten-second Preferences flush measured by E8. Implement candidate bootstrap and token-correlated registration before opening registered identifiers; test shared Downloads, stale registrations, and a newly installed running profile without preseeded records.

7. **High — [package/build.mjs:26](../../../../scripts/poc-cross-profile/package/build.mjs#L26).** The package cannot keep the catalog promised by P4. `LIBRARIES` omits `catalog.sh`, and neither first run nor the daemon invokes it. The extension discovers peers through `registry.json`, so successful window opens and acks do not establish a working rendezvous. Ship and schedule catalog maintenance, including passes where requests are already satisfied. Add a packaged two-profile test that observes registry renewal and peer discovery.

8. **Medium — [open.sh:114](../../../../scripts/poc-cross-profile/open.sh#L114).** Symlink rejection covers leaves but misses ancestors. An ordinary ack beneath a linked `RECnRun`, `poc`, namespace, or `acks` directory is accepted. Presence readers have the same gap; `state_dir()` also follows an existing `profiles` symlink when writing state. This falls short of decision 11's component-by-component policy. Apply a shared no-follow check to every controlled path component and test ancestor links as well as linked leaf files.

9. **Medium — [open.sh:62](../../../../scripts/poc-cross-profile/open.sh#L62).** Record validation does not enforce the documented request surface. Unknown fields and duplicate keys are ignored, and parsing returns immediately after the selected block, allowing invalid later blocks to escape validation. `is_directory()` accepts quotes and literal `$(...)`, contrary to the record's restricted ASCII grammar. Quoting prevented execution in the probe, but the required refusal did not happen. Validate the complete raw record, all field grammars, duplicates, and required fields before launching anything.

10. **Medium — [lifecycle-state.sh:6](../../../../scripts/poc-cross-profile/lifecycle-state.sh#L6).** Accepted numeric state can terminate lifecycle processing during arithmetic. `is_count()` accepts leading-zero values; the probe accepted `attempts=08`, then `$((st_attempts + 1))` exited 127 with an invalid-base error. It also accepts zero as a PID. Require canonical decimal numbers with field-specific bounds and positive PIDs, and reject malformed state before effects. Cover counters, timestamps, settings, and lock PIDs.

11. **Medium — [lifecycle.sh:147](../../../../scripts/poc-cross-profile/lifecycle.sh#L147).** Stale presence is incorrectly treated as explicit pause intent. Healthy `linked-silence`, heartbeat, or launcher renewal policies can trigger permanent `paused` state; subsequent PID death is then ignored because `decide()` refuses paused profiles first. Conversely, Disconnect/Forget updates pairing pauses without supplying this launcher policy signal. E9.pause manually invokes shell `stop` and `pause`, so it does not validate the product behavior. Introduce an explicit validated pause policy and exercise Disconnect/Forget, healthy silence, and subsequent crashes separately.

12. **Medium — [e9-rig.ts:250](../../../../tests/experiments/e9-rig.ts#L250).** E9 converts harness failures into measured samples. The blanket catch turns any body exception into `Sample { ok: false }`, including unexpected filesystem, process, or setup failures encountered during measurement. This contradicts `outcome.ts` and PLAN §8, which require harness exceptions to propagate without a verdict. Preserve cleanup in `finally`, propagate unexpected errors, and reserve failed samples for explicit measured assertions. Add an infrastructure-error control proving that no verdict is written.

13. **Medium — [e9-lifecycle.ts:33](../../../../tests/experiments/e9-lifecycle.ts#L33).** Four E9 cells do not meet the required full sample count. Idempotence, backoff, restart, and pause hard-code two samples, and the committed verdicts confirm two observations each. CHECKLIST calls these “full counts,” while PLAN §8 requires three lab samples. Raise these counts to three, rerun the cells, and replace the evidence and corresponding checklist claims.

14. **Medium — [package/README.md:46](../../../../scripts/poc-cross-profile/package/README.md).** The gesture total does not answer §14 question 8. `4 × N + 1` omits the README's verification command and separate autostart command. The host verdict supplies four installation gestures through a constant while installing diagnostically over CDP; it does not measure those gestures or restart prompts. M-P4.a and M-P4.b remain pending. Separate estimated installation steps from observed gestures and count preparation, machine setup, and post-restart actions explicitly.

15. **Medium — [launcher-first-run.spec.ts:159](../../../../tests/host/launcher-first-run.spec.ts#L159).** Host verdicts contain prohibited host paths. This observation records raw stdout/stderr, and committed `P4.6-host.json` includes `/Users/dannyelcf/Documents/...` paths. `P4.3-host.json` likewise records absolute Downloads roots through the shared open helper. Label paths before serialization, including error strings, add a serialized-verdict guard, and regenerate the committed evidence.

16. **Low — [catalog.sh:443](../../../../scripts/poc-cross-profile/catalog.sh#L443).** The catalog split is owed now. This is pre-existing debt, not a regression introduced by this range, but the file has 443 physical lines and approximately 363 nonblank, noncomment lines, exceeding the stated 300-line cap. ShellCheck does not enforce that architectural limit. Split record parsing, registration validation, and publication into sourced libraries while integrating catalog maintenance into P4; retain negative controls across the split.

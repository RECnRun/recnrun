# Codex review of P2

Model `gpt-6.1-sol`, reasoning effort high, `codex exec --ephemeral -s read-only`, 2026-11-04, one run over P2.1–P2.3 (commits `bb9ca6e7..7634f965`: registry schemas, launcher record, `catalog.sh`, silent start and Downloads presence, E4 with the bootstrap token page). Findings as Codex wrote them; the fixes are the `review-fix:` lines of the P2 block in [CHECKLIST.md](../CHECKLIST.md).

## Findings

1. **High — [tests/experiments/fixtures/e4-lab.ts:33](../../../../tests/experiments/fixtures/e4-lab.ts#L33).** E4 can delete personal Downloads data outside Docker. `session()` unconditionally removes `~/Downloads/RECnRun/poc/lab` before launching Chrome; it has no container guard. An in-memory run with filesystem calls mocked confirmed that deletion target outside the container. Reject non-container execution before any filesystem operation, and validate the container’s Downloads root.

2. **High — [scripts/poc-cross-profile/catalog.sh:354](../../../../scripts/poc-cross-profile/catalog.sh#L354).** The writer can follow symlinks outside its intended files. Both predictable temporary names are opened with ordinary `>` redirection, which follows pre-existing symlinks. Scanning also checks only the final `peers`, profile folder, and file: a symlink at `RECnRun`, `poc`, or the namespace bypasses those checks. The lock does not prevent either condition. Validate rendezvous path components below a trusted root, create temporary files exclusively, and reject directory destinations. Add controls for ancestor and temporary-file symlinks.

3. **High — [scripts/poc-cross-profile/catalog.sh:45](../../../../scripts/poc-cross-profile/catalog.sh#L45).** One malformed registration can invalidate the entire catalog. `is_uuid()` permits hyphens wherever its `?` wildcards appear; both shells accepted a profile ID consisting of 36 hyphens and a malformed boot. `is_time()` also accepts `9007199254740992`, which exceeds `RegistrySchema`’s safe-integer limit. These values are copied into `registry.json`, so the extension rejects every peer together. Require hexadecimal digits in every UUID group and enforce the registry’s numeric bounds before adding a peer.

4. **Medium — [tests/experiments/fixtures/e4-run.ts:182](../../../../tests/experiments/fixtures/e4-run.ts#L182).** E4 does not prove that the launcher discovers profile identity from the bootstrap registration. `discover()` discards `found.presence.profileId`; the record receives `peer.profileId`, already obtained by the harness. An in-memory scan returning the wrong profile identity still produced a passing sample and records containing the harness’s identities. Carry the discovered identity into the record, use harness identity only for comparison, and add wrong-profile and duplicate-token controls. Correct the report’s identity-discovery claim until that passes.

5. **Medium — [tests/experiments/fixtures/e4-launcher.ts:83](../../../../tests/experiments/fixtures/e4-launcher.ts#L83).** Harness failures can become hypothesis samples. Directory enumeration catches every error as “no files”; `parsedFile()` similarly hides read failures, and process errors become numeric exit results. `preferencesSample()` also converts every native-reader exception into a measured failure: injecting `spawn plutil ENOENT` returned an ordinary failed sample. Propagate unexpected filesystem and process errors; handle expected absence separately and use `UnavailableError` only for an explicitly unavailable method.

6. **Medium — [apps/extension/src/background/downloads-presence.ts:103](../../../../apps/extension/src/background/downloads-presence.ts#L103).** Unattended presence refresh is unproved. Refresh depends on a worker-local 30-second interval, with no wake source after termination. The silent-start test polls worker storage every 100 ms through CDP, repeatedly attaching to the worker while awaiting the rewrite. Chromium’s `ServiceWorkerVersion::OnRequestTermination` explicitly changes termination behavior when DevTools is attached; its default idle delay is 30 seconds. Add the lifetime hypothesis to the source inventory, provide a wake-capable refresh path, and measure several TTLs without worker inspection. The observed rewrite cannot establish unattended liveness. [Termination source](https://raw.githubusercontent.com/chromium/chromium/156.0.8078.80/content/browser/service_worker/service_worker_version.cc), [idle-delay constant](https://chromium.googlesource.com/chromium/src/%2B/a7c1557075d257ea53ed5227cea70c05d8dc88a4/third_party/blink/public/mojom/service_worker/service_worker.mojom).

7. **Medium — [apps/extension/src/p2p/registry.ts:30](../../../../apps/extension/src/p2p/registry.ts#L30).** The producer’s registration schema does not enforce the catalog’s display-name contract. It accepts quotes, backslashes, internal controls, and up to 64 JavaScript code units; the shell rejects escaped names and limits UTF-8 bytes to 64. Both shells rejected schema-valid `My "Mac"` and forty `é` characters in reproduction. Such profiles publish successfully but disappear from discovery. Define one compatible registration-name contract, handle incompatible existing names explicitly, and test schema-to-catalog compatibility. PLAN decision 11 currently overstates that compatibility.

8. **Medium — [scripts/poc-cross-profile/catalog.sh:269](../../../../scripts/poc-cross-profile/catalog.sh#L269).** Presence freshness has no upper bound. The parser checks only that expiry is later than now; it accepts future creation times, arbitrarily long lifetimes, and inconsistent creation/expiry pairs. Both shells accepted a registration dated a day ahead. Repeated catalog runs can therefore keep a closed profile listed indefinitely, contrary to the stated 60-second bound. Enforce clock skew, expiry ordering, and the permitted TTL, with equivalent schema constraints and negative controls.

9. **Medium — [tests/experiments/e4-samples.ts:148](../../../../tests/experiments/e4-samples.ts#L148).** The closed-profile verdict does not require its advertised pre-expiry behavior. `afterQuit` is recorded but never checked, and the final read need not be `fresh`. In-memory reproduction returned `ok: true` when the first catalog run exited 73 and listed nobody. Require successful publication with A and B immediately after quitting B, followed by successful publication and a fresh A-only read after expiry. Retain the report’s distinction between forced expiry and elapsed-time measurement.

10. **Medium — [scripts/poc-cross-profile/catalog.sh:120](../../../../scripts/poc-cross-profile/catalog.sh#L120).** Record validation silently changes untrusted bytes before validating them. Command substitution strips NUL bytes in both tested shells: `downloadsRoot=/safe<NUL>tail` becomes the accepted `/safetail`. The TypeScript record parser rejects the original input. Validate the raw record’s allowed bytes before storing it in a shell variable, and add a binary-input control requiring exit 65 without rewriting anything.

The committed observations support diagnostic bootstrap forwarding, discovery within known candidate roots, registry reads, forced-expiry removal, and macOS preference extraction. They overstate token-derived identity and unattended refresh; real macOS default Downloads, strict startup, and complete shell discovery remain unmeasured. I exercised the shell-check command: one static check passed, while 24 tests were blocked by sandbox `EPERM` at temporary-root creation. Manifest checks produced 14 passes and 15 failures against existing POC builds lacking the new code. In-memory reproductions confirmed the findings above; existing production guards passed, but HEAD byte-identity was not rebuilt or verified. No Chrome or Docker was started.

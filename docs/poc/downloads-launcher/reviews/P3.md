## Findings

1. **P2 — [apps/extension/src/background/peers.ts:296](../../../../apps/extension/src/background/peers.ts#L296).** A stored template still announces and discovers peers. Startup unconditionally resumes pairing and starts Downloads presence; `roles.mayAct()` has no runtime caller. Its unit tests therefore do not establish P3.4’s template silence requirement. Gate publication, discovery, and pairing on the stored role before startup, and exercise a template through the real startup path.

2. **P2 — [apps/extension/src/background/presence-renewal.ts:42](../../../../apps/extension/src/background/presence-renewal.ts#L42).** Both silent policies lose discovery of new participants after existing presences expire. They consider only authorized peers, so a healthy existing mesh keeps suppressing publication when a newcomer arrives. The newcomer cannot read survivors omitted from the catalog, including their offers. In-memory checks reproduced suppressed renewal and an empty newcomer sighting. E7 tests a known peer quitting, which does not cover this case. Preserve discoverability and test a fresh participant after a full TTL before recommending `linked-silence` as P4’s fallback.

3. **P2 — [tests/experiments/fixtures/e7-launcher.ts:42](../../../../tests/experiments/fixtures/e7-launcher.ts#L42).** The comparison does not ensure that a profile’s newer publication wins. Chrome can replace the file between this read and `rename()`, after which the launcher overwrites the new boot or certificate with its old snapshot. Subsequent renewals preserve that stale snapshot, preventing current signals from matching the advertised boot. An injected interleaving reproduced the old boot and fingerprint winning. Use coordinated publication or separate profile-owned identity/boot data from launcher-owned freshness, and test overlapping publication.

4. **P2 — [apps/extension/src/background/folder-pairing.ts:132](../../../../apps/extension/src/background/folder-pairing.ts#L132).** The answered-offer record remembers only the latest pairing per peer. Answering B overwrites A; after a restart, replaying still-valid A leaves neither the durable record nor the on-disk answer identifying A. `decideFolderSteps()` then answers A again, reproduced in memory. E5’s immediate duplicate test misses A→B→restart→A, so “answers each offer once across a crash” overstates the implementation. Retain every unexpired answered pairing and add that regression.

5. **P2 — [tests/browser/fixtures/downloads-profiles.ts:279](../../../../tests/browser/fixtures/downloads-profiles.ts#L279).** Catalog harness failures can disappear behind passing verdicts. The loop remembers failures, but disposal discards its stop rejection, and `arrive()` ignores the returned stop function. Injecting catalog exit 73 reproduced successful disposal. Separately, `within()` converts arbitrary observation exceptions into ordinary timeouts. This bypasses `outcome.ts`’s distinction between measured failures and harness errors. Propagate unexpected failures after cleanup; catch only explicitly expected absence conditions.

6. **P2 — [docs/poc/downloads-launcher/MANUAL_VALIDATION.md:41](../MANUAL_VALIDATION.md).** The manual recipe fails when followed across the prescribed terminals. `T` and `DL` are assigned in the roots terminal, but the launcher runs in a fourth terminal and observation in a fifth. Those shells do not inherit the assignments; expansion produces `/record` and `/RECnRun/poc/lab`. `REPO` also lacks an executable assignment. Make every terminal block self-contained or explicitly source a shared environment file.

7. **P2 — [docs/poc/downloads-launcher/MANUAL_VALIDATION.md:27](../MANUAL_VALIDATION.md).** The manual setup overwrites existing roots without the host fixture’s safeguards. `mkdir -p` accepts an occupied destination, then redirection replaces its entire `Preferences`, including when Chrome is still using it. Symlinked ancestors are also accepted, undermining the stated throwaway-only restriction. Create an exclusive, marked run directory, reject symlinks, and clean up only that recorded directory after its processes exit.

8. **P3 — [docs/poc/downloads-launcher/PLAN.md:48](../PLAN.md).** Decision 11 still describes the defects that P3.2 fixed: session-only answer tracking, no upper signal bounds, and no presence skew allowance. ARCHITECTURE additionally says pairing pins before answering and Forget removes the pin, contradicting decision 13 and the code. Update these descriptions together so the durable design does not prescribe obsolete trust and recovery behavior.

## Findings

1. **Must fix — counted samples reuse earlier work.** [e13-remote.ts:64](../../../../tests/headless/fixtures/e13-remote.ts#L64) skips OPEN_TAB when a matching tab already exists; line 76 reads cumulative server requests. Consequently, later command samples and all navigation samples can reuse the first navigation. Clone operations exercise only the final clone round. Both verdict files contain three identical navigation observations. **Scenario:** disable OPEN_TAB after its first success; subsequent samples still pass. **Fix:** use a new marker per sample, require a newly reported tab and requests after that sample began, then regenerate the verdicts and report.

2. **Must fix — several completion cells never require server evidence.** [e13-remote.ts:85](../../../../tests/headless/fixtures/e13-remote.ts#L85) checks the marker title, but `commandsSample`, `tabsSample`, and `markerSample` never validate `result.requests`. **Scenario:** supply a cached marker tab with an empty server log; these cells pass, contrary to E13.md’s stated completion criterion. **Fix:** put the ordered, fresh `/start/…` and `/marker/…` checks in the shared completion helper.

3. **Must fix — exclusivity does not assert refusal or process continuity.** [e13-clones.ts:148](../../../../tests/headless/fixtures/e13-clones.ts#L148) checks only the final process count, mode, and headless windows. Exit status and `survivorSame` are observations only. **Scenario:** a cross-mode request returns success while retaining the original process, or replaces it with another process in the same mode; the verdict passes. **Fix:** require the expected exit status, exactly one process before and after, and identical PIDs. Also describe exit 69 accurately: [open.sh:219](../../../../scripts/poc-cross-profile/open.sh#L219) produces it for an ack timeout, rather than an explicit mode refusal.

4. **Must fix — background survival can pass after some links disappear.** [e13-lifecycle.ts:57](../../../../tests/headless/fixtures/e13-lifecycle.ts#L57) records `stillLinked` without asserting it. After stopping the first worker, only the second worker’s continued connection is checked. **Scenario:** closing the dashboard disconnects workers 3 and 4; worker 2 survives and worker 1 reconnects, so the four-worker cell passes. **Fix:** observe every expected link over a defined interval after closing pages, and require all expected links after recovery.

5. **Should fix — the V1 controller never becomes a recorded master.** [e13-lab.ts:310](../../../../tests/headless/fixtures/e13-lab.ts#L310) exposes `masterSide`, but the V1 flow never calls `bindMaster`. Only workers receive their binding. This contradicts [E13.md:12](../experiments/E13.md#method). **Scenario:** the controller has no stored role, so authorization treats it as an unbound worker and accepts reports without the master’s bound-worker restriction. **Fix:** establish and assert the controller’s master role and worker bindings after linking, before measuring commands.

6. **Should fix — executor validation omits the URL length limit.** [executor.ts:90](../../../../apps/extension/src/background/executor.ts#L90) calls `isWebUrl`, which checks only the scheme. **Input:** `https://example.test/` followed by 2,100 characters reaches tab creation when passed directly to `execute`. Frame and page schemas reject it, but ARCHITECTURE.md explicitly promises this restriction again in the executor. Existing executor tests would not detect this omission. **Fix:** validate with `WebUrlSchema` and add executor refusal tests at the length boundary.

7. **Should fix — failure cleanup can leave Chrome running and delete its root.** [chrome.spec.ts:37](../../../../tests/headless/chrome.spec.ts#L37) calls `quit` only after assertions succeed; `finally` merely removes the rig directory. Separately, [e13-lab.ts:264](../../../../tests/headless/fixtures/e13-lab.ts#L264) suppresses shutdown failures before removing roots. **Scenario:** a mode assertion fails, or Chrome outlives the shutdown timeout; the process remains after its files are removed. **Fix:** retain spawned PIDs outside the assertion block, always stop and confirm process exit during teardown, and propagate cleanup failures while preserving roots still in use. The same disposer also suppresses catalog-loop failures at line 263; those should fail the run.

8. **Should fix — an inconclusive X-window search counts as no windows.** [x-display.ts:55](../../../../tests/browser/fixtures/x-display.ts#L55) converts `undefined` from `search` into an empty result. `searchOutcome` deliberately returns `undefined` for `BadWindow`, meaning the search must be retried. **Scenario:** another Chrome window closes during the search while a worker window remains; the headless window check can pass. **Fix:** retry inconclusive searches with a deadline and propagate unresolved observation errors.

9. **Should fix — the bootstrap diagnostic substitutes its own filter for product behavior.** [e13-diagnostic.ts:102](../../../../tests/headless/fixtures/e13-diagnostic.ts#L102) computes `shared` locally instead of reading the product’s shared-tab result. It also never asserts exactly one page target. **Scenario:** remove the product’s extension-page exclusion, or add another extension page target; this diagnostic still passes. **Fix:** inspect the actual sharing path and explicitly assert the page-target count and bootstrap URL.

10. **Must fix — the checklist introduces a broken documentation link.** [CHECKLIST.md:21](../CHECKLIST.md) links to `reviews/P7.md`, which does not exist. **Scenario:** the required documentation gate checks this link and reports a missing target. **Fix:** add the review artifact or leave the future filename as plain text until it exists.

11. **Should fix — direct local headless runs lack a stable evidence directory.** [playwright.headless.config.ts:3](../../../../playwright.headless.config.ts#L3) omits the run-ID initialization present in the browser and experiments configs. **Scenario:** run `test:headless:local` without `RECNRUN_RUN_ID`; each verdict operation derives a new timestamp directory, and the final completeness check cannot collect the hypotheses. Docker’s public command supplies the ID and avoids this defect. **Fix:** initialize the ID once in this config too.

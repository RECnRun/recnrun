1. **High — [tests/host/fixtures/roots.ts:60](../../../../tests/host/fixtures/roots.ts#L60): Existing roots and internal symlink aliases are accepted.** A leaf symlink pointing back to `HOST_FOLDER` passes containment and returns that folder as the Chrome root. Teardown then recursively deletes the entire approved folder. Existing populated roots also defeat the fresh-profile guarantee. **Fix:** create each launch directory exclusively with `mkdtemp`, reject ancestor aliases, and verify directory ownership before deletion.

2. **High — [scripts/test-container.mjs:113](../../../../scripts/test-container.mjs#L113): The promised egress guard is missing.** Docker uses its default network, and the range contains neither `RECNRUN_FORBID_EGRESS` enforcement nor the experiments egress shim described by the plan. Loopback CDP validation does not restrict Chrome’s other connections. **Fix:** enforce outbound restrictions for browser and harness processes, preserving required local traffic, and add a negative control proving external connections fail.

3. **Medium — [tests/experiments/E0-install.spec.ts:80](../../../../tests/experiments/E0-install.spec.ts#L80): Reinstallation contaminates the persistence result.** After persistence fails, the sample reinstalls the extension, reads preferences afterward, and returns success when the reinstalled ID matches. Consequently, failed persistence produces `pass`, and E0.md incorrectly describes the recreated preferences entry as surviving relaunch. **Fix:** capture state before reinstallation; record failed persistence as a `fail` verdict while allowing the spec to pass. Correct the report and regenerate evidence. This also removes the supposed discrepancy with Chromium’s [`CleanUpCdpInstalledExtensions`](https://raw.githubusercontent.com/chromium/chromium/156.0.8078.80/extensions/browser/extension_prefs.cc).

4. **Medium — [tests/harness-scan.ts:27](../../../../tests/harness-scan.ts#L27): Playwright evaluation bypasses the observer guard.** Both `page.evaluate(() => document.body.remove())` and `worker.evaluate(() => chrome.storage.local.clear())` produce no scan findings. The new profile fixture already uses `worker.evaluate` outside the approved wrapper; imported E2E helpers also escape the scan. **Fix:** restrict evaluation APIs to explicitly audited wrappers and scan the helpers reachable from the lab.

5. **Medium — [tests/browser/fixtures/policy-install.ts:76](../../../../tests/browser/fixtures/policy-install.ts#L76): Policy installation can overwrite host-wide configuration.** The guard requires Linux and root, but does not require the test container. A root Linux `:local` run can overwrite `/etc/opt/chrome/policies/managed/recnrun.json`, then delete its previous contents during cleanup. **Fix:** require container execution before packing or writing, create the policy file exclusively, and remove only the file owned by that invocation.

6. **Medium — [tests/experiments/schema.ts:25](../../../../tests/experiments/schema.ts#L25): The schema rejects the writer’s `unavailable` outcome.** `takeSamples()` returns zero samples when policy installation is unavailable, but `samples >= 1` makes `appendVerdict()` throw before preserving the reason. **Fix:** use outcome-specific schemas allowing zero samples only for `unavailable`, require its reason, and separately enforce that unexecuted hypotheses block completion.

7. **Medium — [tests/experiments/schema.ts:20](../../../../tests/experiments/schema.ts#L20): Contradictory approval metadata passes validation.** A verdict with `label: "strict"`, `externalClient: true`, and `install: "loadUnpacked"` is accepted. Downstream decisions therefore cannot trust the strict label. **Fix:** enforce the relationships between label, external-client presence, and installation method with cross-field checks or discriminated schemas.

A cache miss can change Chrome for the same commit; recording the resulting version does not make that version rebuildable. **Fix:** pin and retain the Chrome package version and checksum, updating them deliberately.
